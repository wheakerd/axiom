submission, post, invitation, or message requires its own authorization. The
plan uses repository data and manual report counts only; Axiom will not add
telemetry.

## Metric Definitions

| Metric | 30-day target | Count only when |
| --- | ---: | --- |
| External installations | 10 | An independent person identifies the installed Axiom version and host; downloads, clones, invitations, and maintainer installs do not count |
| Reproducible fresh-session reports | 5 | One report includes host/version, immutable Axiom version, hook-review status, routed prompt, control prompt, visible evidence, and result |
| Public or permissioned case studies | 3 | A complete case may be published publicly or retained privately with explicit permission to count it; an unapproved anecdote does not count |
| Meaningful directory listings | 2 | The entry is visible and installable or linkable in the directory's authoritative published catalog; submissions and open PRs do not count |
| External contributors | 1 | A non-maintainer's substantive issue reproduction, documentation/code contribution, or accepted directory correction is attributable with permission; Stars do not count |
| Routing investigation | 1 | A reproducible false positive or false negative has a recorded expectation, observation, evidence, analysis, and disposition |
| Visit-to-report conversion | Baseline, then improve | GitHub traffic for the same date range supplies unique visitors and completed qualifying reports supply the numerator; no plugin telemetry or cross-user tracking is added |

Stars, forks, impressions, and post reactions are secondary discovery signals.
They do not establish installation, compatibility, or safety.

## Risks And Responses

- **Broad claims outrun evidence:** keep public-beta language and evidence labels.
- **Guardrails add friction:** measure false positives and preserve no-route
  controls; do not broaden triggers to increase apparent usage.
- **Host behavior changes:** record exact versions and recheck official docs at
  each submission.
- **Directory duplication:** submit to one canonical active community list.
- **Uncertain external effects:** define idempotency and verification before the
  first attempt; do not retry blindly.
- **Sensitive reports:** enable private vulnerability reporting before actively
  soliciting security cases and keep public forms sanitized.
- **Maintainer response load:** stagger channels and do not publish everywhere
  on the same day.

## Recommended Release Threshold

A new release narrative is justified only when all repository guards pass on an
immutable candidate, at least five complete fresh-session reports cover both
hosts, at least one independent report exists for each host, every confirmed
routing regression has a documented disposition, installation and hook-review
instructions match current host behavior, and no known high-impact boundary
failure remains unresolved.

Meeting the threshold does not end the public beta automatically. Promotion out
of beta should be a separate evidence-backed decision, not a consequence of the
calendar or Star count.
