# Axiom v0.7.8

Released: 2026-08-21

Version `0.7.8` adds a reviewable black-box routing corpus and bounded host
benchmark protocol for
[Issue #28](https://github.com/wheakerd/axiom/issues/28). It is a compatible
maintenance release: the only installed behavior change is the narrowed
ambiguity precedence described below; public Skill IDs, startup hooks, action
authority, and runtime dependencies remain unchanged.

The immutable Git tag `v0.7.8` will identify this release. Consumers that need
a stable source identity should use that tag rather than a moving alias or
floating branch.

## Highlights

### Routing expectations are public contracts

Ten JSONL files under `evals/routing/` contain 47 stable, versioned cases. Every
public Axiom route has a canonical positive, paraphrase, near miss, cross-route
case, multilingual case, and post-compaction case. The corpus also covers
plan-only and draft-only requests, ordinary no-route controls, ambiguity,
untrusted input, and a post-compaction no-route control.

Each record states its expected and forbidden routes, clarification expectation
and count, lifecycle precondition, mutation authority, risk class, and coverage
labels. A contract change must increment the record's `contractVersion`; a host
failure must not be hidden by silently rewriting the expected outcome.

### Static contracts and host observations stay separate

The standard-library evaluator validates schema shape, unique stable IDs,
coverage, benchmark membership, privacy, result arithmetic, and status
semantics without invoking a model. Host observations use separate append-only
records and must identify a stable run ID, the applied response-schema path and
SHA-256, an immutable Axiom version, tag, commit, and tree, plus the exact host,
model, operating system, lifecycle, repeat count, route evidence, clarification
count, and mutation-attempt state.

The fixed `codex-core-v1` manifest selects 13 cases at repeat count one: six
canonical route positives, three high-impact safety controls, one dual-route
request, one ambiguity case, one multilingual plan-only request, and one
ordinary no-route request. It may not grow, retry, or change order during a
run. Timeout, malformed output, a missing routing gate, or another uncertain
outcome is the first failure and stops every later case. The failed case keeps
known and null fields honestly; later cases remain `not-run`, and incomplete
summary metrics remain null rather than becoming zero.

### The host method is bounded and non-mutating

The method is a documented equivalent of OpenAI's official
[`plugin-eval`](https://github.com/openai/plugins/tree/11c74d6ba24d3a6d48f54a194cd00ef3beea18f9/plugins/plugin-eval)
harness, inspected at immutable commit
`11c74d6ba24d3a6d48f54a194cd00ef3beea18f9`. Each exact corpus request runs in
one fresh installed-plugin session in a disposable workspace, with a read-only
sandbox, approvals disabled, no web or external-service tools, and the reviewed
response schema. Evaluation prompts grant no mutation authority and do not
upload private conversations, credentials, or unrelated workspace content.

Both versioned model-facing schemas use only the Structured Outputs subset
documented by OpenAI. V1 remains byte-for-byte frozen for historical records.
V2 requests only the routing gate, route set, clarification count, and two
mutation fields; route uniqueness remains a deterministic acceptance gate, and
public evidence is generated from validated observer facts rather than model
prose. This protocol repair does not rewrite any preserved outcome.

The recovery-2 observer applied a reviewed stderr-v2 policy before
acceptance. It removes ANSI/control characters, exact-allowlists only the known
temporary PATH-alias warning, retains capped counts, overflow flags, and fixed
enum categories without raw lines or hashes, and treats every unexpected line
as fatal. Synthetic inputs containing private paths, tokens, userinfo URLs, and
high-entropy fragments verify that those values never enter retained metadata.

OpenAI's official
[non-interactive-mode documentation](https://learn.chatgpt.com/docs/non-interactive-mode)
documents progress on stderr, JSONL events on stdout under `--json`, and stable
structured final data under `--output-schema`. Consequently, the first three
frozen Codex `FAIL` records are harness-policy failures rather than demonstrated
route mismatches. That later documentation context does not reclassify or
rewrite any recorded outcome.

## Compatibility and package shape

- Both plugin manifests declare version `0.7.8` and continue to point to
  `./skills/`.
- The seven direct public Skill IDs and package shape, both hook definitions,
  and both GitHub Actions workflows are unchanged.
- `evals/`, the evaluator module, and focused tests are contributor and CI
  infrastructure. They add no installed daemon, background process, updater,
  network check, credential access, or third-party runtime dependency.
- V2 changes only the bounded observation protocol; it does not change the 47
  corpus contracts, the fixed 13-case order, installed route behavior, or
  authenticated Claude Code's `UNAVAILABLE / NOT-RUN` status.
- `evidence/release-status.json` marks v0.7.8 `STATIC-ONLY`; Candidate 4 is an
  unreleased-candidate host pass, not evidence for the still-uncreated immutable
  v0.7.8 release identity.

## Release validation

The candidate is validated from disposable copies outside the publishable
tree. The local workflow covers:

- schema validation for all 47 corpus cases, the fixed 13-case manifest, and
  nine labeled host records;
- focused routing-evaluation unit tests, including duplicate IDs and keys,
  coverage gaps, invalid status arithmetic, observational claims in unexecuted
  records, and private-data patterns;
- distribution drift, compatibility evidence, JSON, strict YAML, Markdown,
  English-only content, package shape, file-size, repository-link, and aggregate
  publication checks; and
- exact diff, whitespace, and repository-relative invocation checks.

The aggregate passed with 44 required files, 47 black-box cases, 13 fixed host
benchmark cases, nine labeled result records, version `0.7.8`, and all existing
publication fixtures. All 45 standard-library unit tests passed, including the
25 focused routing-evaluation tests. Five fresh aggregate runs of the terminal
Candidate 4 evidence tree measured 0.27, 0.27, 0.25, 0.27, and 0.26 seconds,
for a 0.27-second median. Five fresh runs of immutable Candidate 4 subject
`70e1242ba9f038fe663f924f167108d8940106a8` measured 0.29, 0.29, 0.29, 0.29,
and 0.29 seconds, for a 0.29-second median.

## Known limits

- Post-compaction expectations are statically covered, but no compaction
  lifecycle is claimed unless a host run actually observes it.
- The initial failed Codex process produced no bounded route response. Both
  recovery responses matched Case 1, but their unexpected stderr
  classifications prevent a pass. The safely retained results do not retain
  raw stderr or diagnose the unclassified lines.
- Recovery-3 establishes a semantic ambiguity regression: Case 11 selected two
  routes with no clarification instead of deferring route selection and asking
  one question. The candidate contains a static semantic repair; Candidate 1
  passed ten fresh cases but returned malformed output for the critical case,
  while Candidate 2 passed eight cases before its legacy combined classifier
  stopped at Case 9. Candidate 3 passed seven cases before its closed evidence
  acceptance gate stopped at Case 8. Candidate 4 then passed all 13 cases with
  prose-free V2 output and observer-derived evidence, including the repaired
  critical ambiguity behavior. This remains an unreleased-candidate pass rather
  than a published-release pass.
- No authenticated Claude Code startup, compaction, routed, or no-route case is
  claimed.
- `actionlint` remains optional and is reported `NOT-RUN` if unavailable. No
  workflow file changes in this release.
- Pull-request, merged-`main`, immutable-tag, and GitHub Release runs are remote
  publication evidence and are not claimed by local validation.
- The immutable `v0.7.8` tag, not a moving alias, is the stable release identity.
