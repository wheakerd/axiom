# Axiom v0.7.3

Released: 2026-08-20

Version `0.7.3` hardens traceable Git transactions and the release publication
boundary after the `v0.7.2` audit. It adds no public Skill and does not broaden
ordinary edit, commit, push, fetch, deployment, deletion, credential, or
cleanup authority.

The immutable Git tag `v0.7.3` identifies this release. Consumers that need a
stable source identity should use that tag rather than a moving alias or
floating branch.

## Highlights

### Checkpoint commits remain bound to the authorized tree

`traceable-git-submit` now creates checkpoint candidates directly from the
frozen staged tree and installs a direct-branch candidate with a compare-and-
swap update. A concurrent index change remains staged instead of leaking into
the commit, and a concurrent branch move stops the transaction before the
candidate replaces it.

The same workflow derives the effective push destination independently from
the fetch upstream, following explicit target, branch `pushRemote`, and
`remote.pushDefault` precedence. A locally consolidated result can bind one
previously unbound push target under later explicit push authority, after which
the recorded target remains immutable.

### Git-controlled text is treated as hostile input

Commit subjects and related metadata are validated as bytes before terminal or
commit-message use. Invalid UTF-8, C0 and C1 controls, line separators, bidi and
format controls, and structural separators stop the workflow; accepted text is
rendered through the documented reversible representation.

### Publication guards cover indirect capabilities and their real workflow

Action-pin validation now follows repository-local composite actions and
reusable workflows so an indirect moving third-party Action cannot hide behind
`uses: ./...`. Protected plugin and marketplace manifests use exact schemas
that reject unowned runtime capability surfaces such as MCP servers, apps, or
commands.

Release tags must be strict `v<major>.<minor>.<patch>` values that match both
manifest versions and represent one non-forced creation event. The publication
guard executes the exact JavaScript extracted from the release workflow against
positive and negative event facts, and a mutation fixture proves that a
creation-gate bypass is rejected.

## Compatibility and package shape

- Both plugin manifests declare version `0.7.3` and point to `./skills/`.
- The seven direct public Skills and both platform-specific hook wrappers are
  unchanged in number and identity.
- Existing `0.7.2` installations remain compatible; the host controls when a
  newer installed snapshot becomes active in a session.
- The release adds no implicit external effect or persistent-system-change
  authority.

## Release validation

The release candidate was checked from the repository and, for validators that
could write, from a disposable copy outside the publishable tree. The recorded
workflow verified:

- distribution and publication agreement for 24 required files, 6 JSON files,
  53 Markdown files, 30 routing-contract fixtures, 56 traceable-Git contract
  fixtures, 12 external-action gate fixtures, 10 rollback gate fixtures, 4
  source-linked cross-route and resume contracts, 17 parser fixtures, version
  `0.7.3`, 5 manifest-schema cases, 15 release-tag cases, transitive local
  Action-graph fixtures, and 2 immutable Action pins;
- both manifests and marketplace descriptors, both declared hook files, exact
  documented hook commands, public links, strict protected YAML schemas,
  packaged Skill layout, lifecycle commands, and synchronized version
  metadata;
- all seven packaged Skills with the local Skill Creator quick validator;
- Claude Code `2.1.220` strict plugin and marketplace validation, English-only
  public definitions, instruction-size limits, whitespace, and absence of
  private or generated artifacts;
- focused disposable Git behavior for frozen-tree checkpoint construction,
  compare-and-swap branch installation, effective push-target precedence,
  one-time target binding, and hostile metadata rejection; and
- the exact release-workflow JavaScript against fifteen event cases, plus a
  mutated gate variant whose creation-only check was weakened and correctly
  rejected by the publication validator.

The bundled local `plugin-creator` validator rejects the Codex manifest's
intentional `hooks` field. This remains a validator discrepancy, not a pass;
Claude Code strict validation and Axiom's direct manifest and hook checks pass.

## Known limits

- Static contract fixtures do not prove model route selection in a fresh host
  session or the semantics of a connected service.
- Codex Security Deep Scan was not run because the available session lacked its
  required managed filesystem permission profile; no Deep Scan result is
  implied.
- Focused Git probes ran on Linux; other supported operating systems and Git
  versions rely on the documented version-aware stop boundary.
- A fresh installation, fresh-session route-selection test, real external app
  action, and real persistent system change were not run.
- The immutable `v0.7.3` tag, not a moving alias, is the stable release
  identity.
