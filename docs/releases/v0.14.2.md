# Axiom v0.14.2

Version `0.14.2` makes every skill invocation visible through a short `Axiom:<skill-name>` notice. The skill's own entry point names the exact skill; the shared [notice contract](https://github.com/wheakerd/axiom/blob/v0.14.2/skills/using-axiom/references/skill-notices.md) owns timing, repetition, and source-inspection boundaries.

## Invocation Behavior

The notice appears before workflow actions for direct calls, automatic routing, startup, and calls from another skill. Each newly selected invocation gets one notice, including after a later request or resume. Continuing tool calls and reference reads do not repeat it. Inspecting skill source does not activate the skill.

The startup router's old silent no-match instruction is removed. An invoked router displays `Axiom:using-axiom` and ordinary requests then continue through the host without selecting another skill. Existing route, consent, authorization, and stop conditions continue to apply. No configuration or confirmation is required for the notice itself.

## Evidence Boundary

The candidate is `STATIC-ONLY`. Repository validation and source review do not establish delivery in a newly installed Codex session. Installation, startup, resume, compaction, and actual visible notices remain `NOT-RUN` for this candidate. The marketplace retains its existing published selection.
