# Axiom v0.3.1

Released: 2026-07-31

Version `0.3.1` makes Axiom easier to inspect, install, evaluate, and
contribute to without changing its four public workflows. The Codex and Claude
Code distributions still use one shared `skills/` source through separate,
reviewable manifests and hooks.

The immutable Git tag `v0.3.1` identifies this release. GitHub's Latest Release
marker is remote metadata and remains distinct from the repository's older
floating `latest` Git tag.

## Highlights

### Observable first use

The README now starts with a short, host-specific installation path and asks a
new user to inspect the installed hook before testing Axiom. The first-use
sequence compares one explicit `agents-architect` request with one ordinary
control request, making both routing and intentional non-routing observable.

The new getting-started guide expands that sequence for Codex and Claude Code,
including bounded troubleshooting that does not delete caches, rewrite host
state, or silently replace an installed plugin.

### Reviewable product boundaries

New public documents describe:

- the separation between platform wrappers, hooks, the startup gate, task
  skills, and host-native execution;
- authority, action authorization, credential, mutation, evidence, hook, and
  update trust boundaries;
- routed, non-routed, and ambiguous request examples; and
- checked-in compatibility surfaces separately from historical validation,
  documentation-derived expectations, and unverified runtime behavior.

These documents keep route selection separate from permission to edit, commit,
push, deploy, delete, promote, or use credentials.

### Contributor and publication safeguards

The release adds contributor guidance, focused GitHub issue forms, and a pull
request template. It also adds an offline publication validator that checks the
accepted public documentation set, synchronized manifest versions, shared skill
roots, exact hook declarations, documented hook parity, local Markdown links,
and the packaged skill shape.

The existing read-only GitHub Actions workflow now runs both the distribution
drift guard and the publication validator. Checkout credential persistence is
disabled, repository permissions remain read-only, and the job retains its
bounded timeout.

## Compatibility and package shape

- Both plugin manifests declare version `0.3.1` and point to `./skills/`.
- The public direct skills remain exactly `using-axiom`, `agents-architect`,
  `traceable-git-submit`, and `reversible-system-change`.
- Codex and Claude Code keep independent manifests, marketplaces, and hook
  files; no platform-specific copy of a public skill was introduced.
- Axiom still installs no service, daemon, watcher, polling job, background
  cache refresher, automatic updater, or runtime dependency.

## Release validation

The release candidate was checked from a disposable copy where validation
could mutate files. The recorded release workflow verified:

- distribution agreement among the skill tree, both manifests, both
  marketplace wrappers, and the README shared-skill list;
- publication invariants, including required public files, JSON structure,
  manifest version agreement, exact hook shapes, documented hook commands,
  local Markdown links, and packaged skill layout;
- JSON and GitHub Actions YAML parsing, instruction-size limits, English-only
  public definitions, whitespace, and absence of generated or private
  maintenance artifacts; and
- strict Claude Code `2.1.220` marketplace and plugin validation.

Codex CLI `0.146.0` did not expose a plugin-validation command. The bundled
local `plugin-creator` validator returned a failure for the Codex manifest's
`hooks` field even though its accompanying field guide defines `hooks` as a
supported string path. Axiom retains that intentional integration surface, and
the local result is recorded as a validator discrepancy, not a pass.

`actionlint` was unavailable. The workflow parsed successfully as YAML and its
permissions, checkout credential handling, commands, and timeout were reviewed
directly, but those checks are not reported as an `actionlint` pass. The
release checks establish the observed repository and tool results only; they
do not prove behavior on every host version, operating system, shell, trust
policy, or installed session.

## Known limits

- Axiom routes only the requests covered by its focused workflows; a no-route
  result is intentional for ordinary work.
- Loading a route does not authorize a repository or system mutation.
- Installed hooks remain a host trust decision and should be compared with the
  exact checked-in commands after installation or refresh.
- Marketplace caches and existing sessions may lag the release until the user
  explicitly refreshes or reloads them.
- Axiom does not automatically check for, download, install, or announce
  updates.
- The floating Git tag `latest` is not moved by this release. Use the immutable
  `v0.3.1` tag for source identity and GitHub's Latest Release marker for the
  current GitHub release.
