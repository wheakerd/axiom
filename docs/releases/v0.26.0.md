# Axiom v0.26.0

Version `0.26.0` is the measured follow-up to Issue #240. A private audit of the maintainer's sessions, kept as categories and counts and recorded in the [v0.25.0 note](v0.25.0.md#private-audit-behind-issue-240), found that the startup gate selected a bundled route too rarely when the gate was delivered and trusted. This release changes the gate's wording where the misses concentrated, adds the missed request forms to the routing corpus, and records a two-arm fresh-session measurement of the current and candidate wording on both hosts; the description changes that two earlier candidates carried were measured and dropped.

## Why A Minor

The [release standard](../runtime-identity.md#version-increment) assigns a minor increment when matching widens to requests a route did not select before. The not-displaced boundary makes a request route where the host's own tool or an unnamed repository-local skill was read as displacing the bundled route, and the requests-only item narrows routing on notifications and tool results in the same change.

## What Changed

- Not-displaced boundary: the gate's selection paragraph reads that a more specific installed skill, MCP tool, or host tool the user named is not displaced by a bundled route, and adds that a tool the host merely offers, such as its own subagent facility, or a repository-local skill the user did not name, displaces nothing. The audit classified seven clear misses as this gate-rule interaction.
- Requests only: Route Once gains item 6, that a host task notification, tool result, or compaction summary is not a request and selects no route. Three of the audit's seventeen unneeded selections fired on notifications.
- Selection surface: the Route Once sentence that restated the `local-web-search` condition leaves the gate, because the description is the selection surface and already states that condition; the description itself is unchanged.
- Descriptions: unchanged. Two earlier candidates carried description changes, a `delegate-simple-task` widening and then `local-web-search`, `review-axiom-task`, and `agents-architect` wording; the two-arm measurement below dropped both sets, and every description keeps its 0.25.0 text.
- Corpus: eighteen schema v8 cases join `evals/routing-v8/current.jsonl` outside both benchmark profiles, eleven positives for the missed forms and seven controls for the wrongly routed or named-host-tool forms; [Routing Evaluations](https://github.com/wheakerd/axiom/blob/v0.26.0/evals/README.md) lists them. Benchmark membership follows a later contract once the forms prove stable on both hosts.
- Documentation: the [Trust Model](../trust-model.md#authority-across-workflows), [Architecture](../architecture.md), and [Examples](../examples.md) describe the boundary; the Simplified Chinese twins change with their sources.

## Two-Arm Measurement

The eighteen new corpus cases ran as two arms on each host on 2026-11-02, each case in a fresh isolated session with the arm's plugin tree loaded natively, the benchmark developer instruction, and response schema V8: arm A is the 0.25.0 plugin tree and arm B the candidate. The decision rule is the gate-reduction policy: the candidate must match or exceed the current wording on routed and no-route cases per host with no no-route regression. A host failure, a 300-second stall with no model event or a "model at capacity" stream error, was rerun once in a new session and the rerun's decision counted. Three candidates were measured in sequence:

1. The first candidate changed the gate and four descriptions. On Claude Code it passed 18 of 18 against 17 of 18 for the current wording before the one stall was rerun. On Codex it selected `delegate-simple-task` for the control that names the host's own subagent tool, which the current wording leaves host-native, so the `delegate-simple-task` widening was dropped.
2. The second candidate kept the gate change and the `local-web-search`, `review-axiom-task`, and `agents-architect` wording. On Claude Code it passed 18 of 18. On Codex the project-initialization control selected `reversible-system-change` under the candidate while the current wording left it host-native; four alternating trials per arm gave the current wording 4 of 4 and the candidate 3 of 4 host-native, so the description changes were dropped as well.
3. The third candidate is this release: the gate change alone, every description at its 0.25.0 text. Claude Code 2.1.309 with `claude-opus-5-5` at maximum effort: routed 11/11 under A and 11/11 under B, no-route 7/7 under A and 7/7 under B. Codex CLI 0.166.0 with `gpt-6-astra` at maximum effort: routed 10/11 under A and 10/11 under B, no-route 7/7 under A and 7/7 under B; the project-initialization control stayed host-native in 4 of 4 further trials under A and 4 of 4 under B. Per-route misses before and after on Claude Code: no route missed under either arm; on Codex: `reversible-system-change` 1 to 1.

Under both arms and every candidate, Codex selects `confirm-external-action` together with `reversible-system-change` for the deployment to a remote staging host, where Claude Code selects `reversible-system-change` alone; the case keeps its single expected route and stays outside the benchmark as a recorded host disagreement. The measurement also shows the limit of the method: in fresh sessions the 0.25.0 wording already routes every other form the private audit found missed, so the audit's misses arise in long sessions with tools, prior turns, and compaction, which this fresh-session method does not reproduce. The gate change therefore targets the gate-rule interaction the audit classified and is measured here for the absence of a regression; the eighteen forms stay in the corpus for later contracts, and an in-session measurement method is the open follow-up of Issue #240. Raw outputs stay in the maintainer's private record.

## Routing Contract

Routing contract v8 and its two host benchmark profiles keep their 49 cases; the eighteen new cases stay outside both profiles. ## Host Evidence

The release gate introduced by repository policy revision 118 requires one checked-in fresh-session observation record per host for this candidate under `evals/results/v0.26.0/`, bound to this runtime digest, before the pipeline publishes. Both records observe candidate commit `2937e5f7a2b98c093ceac641913a5b646f505035` (tree `8405aeeb2065cf418a77bfbe723a223caf2dc961`) on one Fedora Linux 44 x86_64 machine with the candidate installed in an isolated host configuration. The [Claude Code record](https://github.com/wheakerd/axiom/blob/v0.26.0/evals/results/v0.26.0/claude-code/linux.json) comes from Claude Code 2.1.309 with `claude-opus-5-5` at maximum effort and passes all 49 `claude-code-core-v8` cases in run `claude-code-v0-26-0-linux-claude-code-core-v8-candidate-1`; for the invocation the installed Axiom plugin and two other installed plugins that declare SessionStart hooks were disabled so that exactly one hook response, the candidate's, reached the classifier. The [Codex record](https://github.com/wheakerd/axiom/blob/v0.26.0/evals/results/v0.26.0/codex/linux.json) comes from Codex CLI 0.166.0 with `gpt-6-astra` at maximum effort and passes all 49 `codex-core-v8` cases in run `codex-v0-26-0-linux-codex-core-v8-candidate-1`, with the candidate installed from a local marketplace into an isolated home whose configuration records trust for the packaged SessionStart hook through the documented app-server handshake. As in 0.25.0, the 30 feature overrides that Codex CLI 0.166.0 reports as deprecated or removed were omitted, `features.hooks` and `features.code_mode_host` stayed at their defaults, `features.plugin_discovery_prefetch` was disabled, and the `rmcp` transport logger was silenced; in addition the `codex_models_manager` logger was silenced because on 2026-11-03 a few sessions wrote a non-causal "failed to refresh available models: request timed out" line to stderr while their turns completed normally. The JSONL stream of every case shows no tool-capable item. These records are pre-publication observations, not a publication or installed-host lifecycle observation.

On 2026-11-03, while measuring Issue #249, the maintainer found that both records above were collected in case workspaces that lay inside the maintainer's own repository, so each host also loaded that repository's root instruction file beside the Axiom gate: Codex resolves the project root to the nearest enclosing Git repository and loads its root `AGENTS.md`, and Claude Code loads instruction files from the working directory and its ancestors. The records keep their lifecycle and outcome; Issue #251 records the deviation, and the fresh-session method now requires a workspace outside any instruction chain. On 2026-11-04 the immutable `v0.26.0` tag (commit `c8126c54b3d77bba79bee90a49fcc0e675315a56`) was observed again on the same machine in such a location under the unchanged contracts. Claude Code 2.1.309 with `claude-opus-5-5`: the first run stopped at the twelfth case, the overlap request expecting `agent-plugin-architect` with `optimize-agent-usage`, which selected the first route alone; the recovery run `claude-code-v0-26-0-linux-claude-code-core-v8-release-2` passed all 49 cases and is checked in as the [Claude Code clean-location record](https://github.com/wheakerd/axiom/blob/v0.27.2/evals/results/v0.26.0/claude-code/linux-release-2.json). Codex CLI 0.166.0 with `gpt-6-astra`: the first run and the recovery run `codex-v0-26-0-linux-codex-core-v8-release-2` both stopped at that same case with the same single route after the same 11 passes, so no Codex clean-location record is checked in. The overlap case therefore missed `optimize-agent-usage` in 1 of 2 Claude Code trials and 2 of 2 Codex trials in a clean location, where both confounded records had selected both routes; Issue #253 owns that finding. The stopped runs stay in the maintainer's private record under their own run IDs.

## Unchanged Boundaries

Routing still selects instructions only. A notice grants nothing, `delegate-simple-task` still needs the user's consent and, outside a permission-bypass mode, the model-and-brief confirmation, and every authorization, rollback, untrusted-input, and stop rule stays hard. A named host tool or repository-local skill is still not displaced by a bundled route.
