# Axiom v0.8.1

Released: 2026-08-23

Version `0.8.1` is an evidence-only patch release for the failed Stage 3
attempt tracked by [Issue #34](https://github.com/wheakerd/axiom/issues/34).
It preserves the terminal result, strengthens the existing evaluation
validator, and leaves the Issue open for a separately authorized diagnosis and
fix. It does not change the `agent-plugin-architect` route contract or claim
Stage 3 acceptance.

The immutable Git tag `v0.8.1` will identify the published release. This local
candidate does not create a tag, GitHub Release, pull request, Issue mutation,
or other remote state.

## Preserved Codex Result

The append-only run
`codex-v0-8-0-linux-codex-core-v2-initial` is bound to Axiom tag `v0.8.0`,
commit `5d02ebaa94f2a4355cb185a5091153c9e4ec497c`, and tree
`974c0f5db0f2dab0aba512a6633b0a22b0d80779`. It used Codex CLI `0.149.0`,
model `gpt-5.4`, medium reasoning, a 120-second case timeout, Fedora Linux 44
x86_64, the fixed 17-case `codex-core-v2` order, and
`host-response-schema-v3.json` at SHA-256
`29247831a414e74cc9f36594e52cfeca6a0eb0d862c34eb761db04437df2fed6`.

Case 1 returned a valid V3 response. The routing gate was observed, the sole
route was `agent-plugin-architect`, clarification count was zero, and
`mutationObserved` was false. The observer nevertheless derived
`mutationAttempted=true` after two unexpected tool events. It also recorded a
clean `turn.completed`, no failure event, and unchanged workspace, source, and
installed snapshots.

The stop-on-first-failure policy therefore produced terminal `FAIL` after one
call and 17,984 milliseconds. Cases 2-17 are `NOT-RUN`, no case was retried,
and the two tool-event categories are neither retained nor inferred. The
bounded record contains no raw private response, credential, session
identifier, absolute temporary path, or arbitrary diagnostic text.

and 116 output tokens; credits were not exposed. The existing context-budget
schema stores the input, cached-input, and wall-clock values. It has no output
token field, so the output value remains documented here and in the routing
evaluation guide. The static measurement itself remains local and
telemetry-free, while the separately authorized model call necessarily used the
host network; the combined context record reports that boundary explicitly.

with 64 corpus cases, 30 benchmark memberships, 11 labeled host records, seven
context scenarios, and the existing manifest, hook, release-provenance, and
repository-governance fixtures. Distribution, compatibility, context-budget,
duplicate-aware data, link, fragment, ASCII, package-shape, and historical-byte
checks pass.

Claude Code `2.1.220` strict offline package validation passes in an isolated
configuration directory; it is not authenticated host behavior. The bundled
`plugin-creator` retains exactly its known stale non-pass for `hooks`,
`interface.brandColorDark`, and `interface.supportURL`; that diagnostic is not
weakened into success.
