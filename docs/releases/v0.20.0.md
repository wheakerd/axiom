# Axiom v0.20.0

Version `0.20.0` makes each host's native skill list the selection surface of the always-loaded startup routing gate `plugin/skills/using-axiom/SKILL.md`. The gate's thirteen Bundled Routes entries, about 3.2 KB of catalog text that restated each skill's description, give way to one selection paragraph: select a bundled skill from the host's listed skills by its description; an explicit `Axiom:<skill-name>` invocation selects that skill; a more specific installed skill, MCP tool, or host tool the user chose is not displaced by a bundled route; no match continues host-native. Every composition rule, boundary, resume rule, and refresh rule stays. Three descriptions carry the selection conditions their gate entries had held. Hooks and every manifest field other than the version are unchanged. The [runtime identity](../runtime-identity.md) owns the digest and policy revision.

## Why A Minor

Issue #194 asked whether the gate needs its catalog at all when both hosts already show their model every bundled skill with its description. The [release standard](../runtime-identity.md#version-increment) classifies a changed selection mechanism and a new precedence rule as a minor increment: no route is added or removed, but the way every route is selected changes, and a more specific skill or tool the user chose now keeps its place.

## What Changed

- The gate's Bundled Routes section keeps its heading and replaces the entries with the selection paragraph above; "Resolve cross-route ownership from this table" becomes "from these rules". The Invocation Notes add the hand-off clause: when a bundled route hands off to, or yields to, another installed skill or MCP tool, name it the same way with a brief reason.
- `delegate-simple-task`'s description adds "when only consent is missing, it asks and waits"; `review-axiom-task`'s description adds "A prior refusal governs neither a review nor a narrower request."; `traceable-git-submit`'s description carries the full ordinary-Git exclusion: ordinary named-remote non-force staging, commits, and pushes without a tag, checkpoint, baseline, consolidation, recovery, hardening, multiple targets, or history replacement stay host-native, and merely mentioning submit, publish, or push does not select the route.
- The gate shrinks from 7,368 to 4,648 bytes. The 0.19.3 Changelog entry stated 7,371 bytes for that gate; the tagged v0.19.3 file measures 7,368, and this note records the correction.
- The validators that pinned the catalog now pin the descriptions: the selection anchors, the shared Git boundary anchors, the structured route catalog anchors, the `effective-instructions` trigger tokens, and the ordinary-Git no-route anchor are checked in each skill's description; the gate is checked for its selection paragraph and may not re-declare a catalog; the Skill Reference inventory is checked against the canonical skill order.
- The Architecture, Trust Model, and Skill Reference pages describe the selection surface and the precedence rule.

## Measurement

The decision came from one same-batch fresh-session benchmark per host: the 36 `codex-core-v6` and `claude-code-core-v6` cases plus the explicit `delegate-simple-task` request repeated four times, each run a new session against the exact candidate installed from a local marketplace, response schema V8, Codex CLI 0.164.0 with `gpt-6-astra` at maximum reasoning effort and Claude Code 2.1.308 with `claude-opus-5-5` at maximum effort. The rule: the thin gate matches or exceeds the current gate's routed and no-route counts per host, no no-route control regresses, and the delegate request routes 4 of 4 on both hosts.

- Claude Code: current gate 39 of 39 (26 routed, 10 no-route, delegate 4 of 4); thin gate 39 of 39 with the same split.
- Codex: current gate 38 of 39 (26 routed, 9 no-route, delegate 4 of 4); thin gate 39 of 39 (26 routed, 10 no-route, delegate 4 of 4); the thin gate alone passed `current-no-route-progress-evaluation-001`.

The benchmark is a candidate observation on one machine; it is not a publication, installed-host lifecycle, or usage observation.

## Limit

The native list's content, order, and truncation are host-owned; the gate infers nothing from a listing it cannot see, and only an explicit invocation selects a skill the host does not show. Descriptions are now load-bearing: a description edit is a routing change and takes the same fixed-corpus and both-host evidence as a gate edit did.
