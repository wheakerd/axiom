# Axiom v0.7.4

Released: 2026-08-21

Version `0.7.4` fixes Axiom's Claude Code compaction lifecycle integration.
It removes an ineffective pre-compaction context loader and keeps the supported
post-compaction `SessionStart` path without changing Axiom's public Skills or
granting any new authority.

The immutable Git tag `v0.7.4` identifies this release. Consumers that need a
stable source identity should use that tag rather than a moving alias or
floating branch.

## Highlights

### Compaction routing uses the context-bearing lifecycle event

Claude Code adds successful `SessionStart` stdout to model context and emits
the `compact` source after either manual or automatic compaction. Axiom now
uses that path exclusively. The former `PreCompact` handler is removed because
ordinary successful stdout from that event is not injected into model context.

This follows Anthropic's current
[hooks reference](https://code.claude.com/docs/en/hooks) and
[hook guide](https://code.claude.com/docs/en/hooks-guide). The checked-in
wrapper still performs only foreground output and one local read of
`skills/using-axiom/SKILL.md`.

### Lifecycle claims and troubleshooting are synchronized

The README, architecture, compatibility, getting-started, field-validation,
contributor, and launch documents now describe one Claude Code `SessionStart`
handler. The field protocol records manual and automatic compaction separately,
requires exactly one observed `compact` delivery, and preserves routed and
no-route results as separate evidence.

Publication validation now rejects both a restored Axiom `PreCompact`
context-loading event and a Claude Code `SessionStart` matcher that omits
`compact`.

## Compatibility and package shape

- Both plugin manifests declare version `0.7.4` and point to `./skills/`.
- The seven direct public Skills and both platform-specific hook wrappers are
  unchanged in number and identity.
- Claude Code retains `SessionStart` for `startup`, `resume`, `clear`, and
  `compact`; the Axiom `PreCompact` event is removed.
- Existing `0.7.3` installations remain compatible after the host loads the
  newer plugin snapshot.
- The release adds no file write, network request, background process,
  telemetry, credential access, or authorization expansion.

## Release validation

The release candidate was checked from the repository and, for validators that
could write, from a disposable copy outside the publishable tree. The recorded
workflow verified:

- distribution and publication agreement for 25 required files, 6 JSON files,
  63 Markdown files, 30 routing-contract fixtures, 56 traceable-Git contract
  fixtures, 12 external-action gate fixtures, 10 rollback gate fixtures, 4
  source-linked cross-route and resume contracts, 17 parser fixtures, version
  `0.7.4`, 5 manifest-schema fixtures, 3 hook-lifecycle fixtures, 15
  release-tag fixtures, and 2 immutable Action pins;
- both manifests and marketplace descriptors, both declared hook files, exact
  documented hook commands, public links, protected schemas, packaged Skill
  layout, lifecycle commands, and synchronized version metadata;
- Claude Code `2.1.220` strict plugin and marketplace validation; and
- the exact Claude Code hook shape and foreground command in a disposable copy,
  plus English-only, brand, changed-YAML, and whitespace checks.

The bundled local `plugin-creator` validator rejects the Codex manifest's
intentional `hooks` field. This remains a validator discrepancy, not a pass;
Claude Code strict validation and Axiom's direct manifest and hook checks pass.

## Known limits

- Static hook and lifecycle fixtures do not prove that a particular installed
  Claude Code version delivered context after compaction.
- Fresh manual and automatic compaction observations were not run because the
  available environment had no Claude Code subscription or authenticated
  session. Exactly one effective injection plus the post-compaction routed and
  no-route cases therefore remain `NOT-RUN` / `UNAVAILABLE`, not passed.
- No packaged Skill changed, so per-Skill quick validation was not run; the
  distribution and publication guards confirmed the unchanged seven-Skill
  package shape.
- A fresh installation, Codex fresh-session route-selection test, real external
  app action, and real persistent system change were not run.
- The immutable `v0.7.4` tag, not a moving alias, is the stable release
  identity.
