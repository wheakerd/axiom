Version `0.8.17` is the governance-policy patch for [Issue #85](https://github.com/wheakerd/axiom/issues/85). It selects Path B: document the single-maintainer trust boundary without changing repository rules, contributor permissions, or installed plugin behavior.

## Documented Human-Review Boundary

The dated repository-governance snapshot now identifies `wheakerd` as the ultimate repository trust root and records the absence of independent human review as a known limitation. CODEOWNERS remains advisory because the live main ruleset requires zero approvals and does not require code-owner review.

The snapshot separates current preventive controls from detective controls. Server-side pull-request, signature, non-fast-forward, strict-check, squash-merge, and release-tag rules constrain operations. Validators, Actions output, signed-target and release observations, content-addressed attestations, read-only API checks, and ruleset history can expose drift or preserve provenance, but they do not create an independent human trust domain.

Hardware-backed authentication and an independently controlled release identity remain unverified and are not claimed as compensating controls. The observed ruleset history maps to the same repository-owner identity, so it remains detective evidence rather than independent oversight.

## Path A Transition Gate

Independent review must not be enabled until a different trusted GitHub principal has direct write access, shares every critical CODEOWNERS path, and approves a protected critical-path test pull request without author self-approval or ruleset bypass. Only after that proof and a live API read-back may the main ruleset require an approval, code-owner review, last-push approval, stale-review dismissal, and review-thread resolution.

## Contributor Boundary

Path B changes no ruleset, CODEOWNERS entry, workflow, collaborator permission, or required check. External contributors keep the same fork, branch, pull-request, and merge gates. `repository-guards` and `unit-and-integration-tests` remain the only required checks; the three hook-runtime matrix checks remain non-required evidence.

Installed Skills, hooks, routes, action authority, benchmark membership, runtime dependencies, and host delivery are unchanged from v0.8.16. The release therefore carries no current installed-host or native-process observation forward from v0.8.16 or any earlier release.
