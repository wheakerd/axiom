Version `0.8.14` is the patch release for [Issue #71](https://github.com/wheakerd/axiom/issues/71). It prevents refusal-target substitution and recursive expansion of a prior refusal while preserving the boundary around raw hidden reasoning, privileged prompts, and private policy text.

## Independent Bounded Review

`review-axiom-task` now evaluates explanation, audit, criticism, appeal, and read-only narrowing from the current observable requested effect. A prior refusal, disagreement, safety phrase, or assistant explanation neither supplies risk evidence nor creates policy. Mixed requests withhold protected hidden content while completing the permitted observable review.

Every decision explanation now identifies the current review effect, selected route or no-route result, concrete observable trigger, reviewed blocked effect and finite material-effect category, permitted remainder, evidence state, and a missing-fact counterfactual when the basis is reconstructed or unavailable. A self-referential refusal terminates at that bounded explanation instead of citing itself as evidence.

The always-loaded gate gains only the precise retrospective and observable-basis trigger. The packaged Skill and Codex UI prompt expose the same behavior, and ordinary summaries, code review, execution, retries, and unrelated work remain outside the route.

## Regression Contract

The route corpus adds six host-independent cases for observable refusal explanation, explicit chain-of-thought exclusion, independent refusal audit, read-only narrowing, criticism, and recursive refusal termination. The combined corpus now contains 73 cases without changing either frozen host benchmark.

A separate validator-owned suite defines eight sanitized same-session sequences with 11 review checkpoints. It covers every Issue edge, including a four-step review, appeal, criticism, and narrowing invariant plus a historical assistant-message injection whose prose must have zero policy authority. Each checkpoint uses a closed, prose-free response schema for route, effect, trigger, bounded category, permitted remainder, evidence state, non-inheritance, non-expansion, zero assistant authority, hidden-reasoning protection, and completion.

The suite adds no persistent runner, transcript, telemetry, service, credential access, external action, or mutation authority. Static validation checks its shape, sanitization, exact expected invariants, response-schema digest, and documented ephemeral host method; it is not installed-host evidence.
