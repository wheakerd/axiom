# Axiom v0.14.4

Version `0.14.4` inlines optional [invocation notes](../../plugin/skills/using-axiom/SKILL.md#invocation-notes)
in `using-axiom`. The startup Hook injects that skill's body, so its naming and
reason rules arrive with the gate without a separate reference read. The old
notice reference is removed; other direct skill entries do not load the rules.

## Activation And Naming

The enabled startup gate or an explicit user invocation activates
`using-axiom` and makes its notice guidance applicable. Gate activation does
not force a visible explanation. With the gate disabled, invoking another
Axiom skill alone does not activate the guidance.

When the model and host choose to explain an invocation, bundled Axiom skills
use the complete inline-code `Axiom:<skill-name>` marker. External skills,
repository-local skills, plugins, and MCP capabilities used by an Axiom
workflow keep their actual
inline-code names and a short goal or reason. They do not acquire an `Axiom:`
prefix or become bundled capabilities through that invocation.

## Native Output Decisions

This replaces the mandatory notice contract introduced in `0.14.2` and the
fixed layout from `0.14.3`. The model and host follow the user's native
output-verbosity preferences to decide whether an explanation is useful and
how to arrange the response. There is no required notice count, separate
commentary message, line break, or paragraph break. No new Axiom setting,
client configuration change, or migration is required.

Skills assist and constrain model capabilities within their existing scope.
Routing, consent, authorization, stop conditions, evidence requirements, and
independently required disclosures remain unchanged. Source inspection and
mere mentions do not count as invocations.
