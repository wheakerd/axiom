# Axiom v0.5.0

Released: 2026-08-15

Version `0.5.0` adds an optional, explicitly triggered review of an
Axiom-guided task. The shared workflow summarizes routing, scope,
authorization, actions, evidence, stops, and outcome without rerunning the task
or introducing a trace service.

The immutable Git tag `v0.5.0` identifies this release. The moving `latest`
Git tag and GitHub's Latest Release marker are synchronized to the same release
commit; consumers that need a stable identity should use `v0.5.0`.

## Highlights

### Explicit task review

`review-axiom-task` activates only when the user explicitly asks to understand
an Axiom-guided task. It freezes the review window immediately before that
request and inspects only the scoped evidence the active host exposes.

The report separates the triggering request, selected route, scope,
authorization, Axiom guidance, host-agent actions, evidence, stops, and outcome.
An ordinary coding-task summary remains outside this route.

### Evidence-aware reconstruction

Material claims are labeled `observed`, `reconstructed`, or `unavailable`.
Current read-only state may verify a present outcome, but it cannot prove past
authorization, causation, hidden reasoning, or which instructions were active.

Missing or compacted history stays unavailable. The workflow does not invent a
complete trace, replay the task, or upgrade command success into proof of the
intended result.

### Shared, foreground-only package

Codex and Claude Code use the same packaged Skill and routing definition. The
hosts may expose different task evidence, so report coverage can differ without
changing the workflow's read-only contract.

The feature adds no telemetry, persistent log, background process, scheduled
work, remote service, automatic upload, credential access, or mutation
authority.

## Compatibility and package shape

- Both plugin manifests declare version `0.5.0` and point to `./skills/`.
- The direct public Skills are `using-axiom`, `agents-architect`,
  `optimize-codex-usage`, `review-axiom-task`, `traceable-git-submit`, and
  `reversible-system-change`.
- Codex and Claude Code retain separate manifests, marketplace descriptors,
  and hook files over the same Skill source.
- Existing route identifiers, hook commands, and explicit update behavior are
  unchanged.

## Release validation

The release candidate was checked from the repository and, for validators that
could write, from a disposable copy outside the publishable tree. The recorded
workflow verified:

- distribution agreement among the Skill tree, both manifests, both
  marketplace wrappers, and the README shared-skill list;
- publication invariants for 17 required files, 6 JSON files, 43 Markdown
  files, manifest version agreement, exact hook shapes, documented hook
  commands, links, frontmatter, reference discovery, and packaged Skill layout;
- fifteen static routing contracts, ten rollback gates, JSON and YAML parsing,
  English-only public definitions, instruction-size limits, whitespace, and
  absence of private or generated artifacts;
- all six packaged Skills with the local Skill Creator quick validator; and
- strict Claude Code plugin validation.

The bundled local `plugin-creator` validator rejects the Codex manifest's
intentional `hooks` field even though Axiom's checked-in wrapper and publication
validator require it. This remains a validator discrepancy, not a pass.

The static scenarios validate checked-in contracts. A fresh Codex or Claude
Code session-level semantic-routing check was not run and is not implied by the
repository checks.

## Known limits

- Review completeness depends on the history, summaries, tool results, and
  task-inspection interfaces exposed by the active host.
- A review cannot expose hidden model reasoning or recover unavailable context.
- Current state can verify a present outcome but cannot prove historical
  authorization or causation by itself.
- Existing installations and sessions may retain `0.4.2` until the user
  explicitly refreshes and starts a new session.
- The moving `latest` tag is a convenience alias, not an immutable source
  identity.
