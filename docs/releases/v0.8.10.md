Version `0.8.10` is the patch release for [Issue #60](https://github.com/wheakerd/axiom/issues/60). It corrects doubled single-quote handling in Axiom's dependency-free canonical YAML comment scanner.

## Canonical Single-Quote Scanning

`split_yaml_comment()` now uses an explicit index-driven state machine. While it is inside a single-quoted scalar, two consecutive quotes are consumed together as one escaped literal quote, so the second quote cannot close the scalar and an internal `#` cannot be misclassified as an inline comment delimiter.

Double-quoted escape tracking, plain-scalar handling, and the existing rule that the first unquoted `#` at the accepted whitespace boundary starts the comment remain unchanged.

## Fail-Closed Scalar Validation

Single-quoted scalar decoding now requires a complete outer quote pair whose body contains only non-quote characters or doubled quotes. Unterminated strings, odd adjacent quotes, and text after a closed quoted scalar fail closed. The implementation adds no third-party YAML dependency and does not accept aliases, tags, merge keys, flow collections, multiple documents, or other content outside the existing narrow subset.

Focused tests cover the reported `can''t # inside` reproduction, multiple escaped quotes, adjacent quote delimiters, empty quoted scalars, internal and external comment markers, escaped backslashes and quotes in double-quoted scalars, malformed tails, carriage returns, tabs, trailing spaces, and YAML document markers. Existing action-pin, workflow-contract, and publication tests continue to pass.
