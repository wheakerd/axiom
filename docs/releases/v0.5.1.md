# Axiom v0.5.1

Released: 2026-08-17

Version `0.5.1` hardens AGENTS Architect task-context maintenance after
conversation compaction. It distinguishes what turns were reviewed from which
raw outputs remain available, preserves later user corrections, and makes the
activation boundary of durable `AGENTS.md` changes explicit.

The immutable Git tag `v0.5.1` identifies this release. The moving `latest`
Git tag and GitHub's Latest Release marker are synchronized to the same release
commit; consumers that need a stable identity should use `v0.5.1`.

## Highlights

### Separate evidence coverage

Task-context maintenance now records the review-window turn coverage,
raw-output coverage, and any unread required history as separate fields. A
compacted summary may cover all visible turns while original tool output is
partial or unavailable; the report must preserve that distinction.

### Controlling decisions survive compaction

Corrections, reversals, and narrowed requests record the latest in-scope user
decision together with superseded proposals and unresolved conflicts. An
earlier proposal cannot re-enter the durable candidate set merely because it
appears in a compaction summary or old plan.

### Explicit activation semantics

Editing `AGENTS.md` does not retroactively replace the instruction chain
already loaded for the current run. Durable updates apply to later in-scope
runs, while current-task state remains the responsibility of a justified
runtime capsule. Fresh host loading is reported as verified only after a new
run or session actually checks it.

### One canonical evidence owner

The context-evidence reference now owns review-window, decision-disposition,
coverage, and retrieval-friction definitions. Update and application paths
route to that owner instead of maintaining duplicate formulations.

## Compatibility and package shape

- Both plugin manifests declare version `0.5.1` and point to `./skills/`.
- The direct public Skills remain `using-axiom`, `agents-architect`,
  `optimize-codex-usage`, `review-axiom-task`, `traceable-git-submit`, and
  `reversible-system-change`.
- Route identifiers, hook commands, marketplace paths, and explicit update
  behavior are unchanged.
- The release adds no new action authorization, telemetry, background work,
  automatic update check, credential access, or runtime dependency.

## Release validation

The release candidate was checked from the repository and, for validators that
could write, from a disposable copy outside the publishable tree. The recorded
workflow verified:

- distribution agreement among the Skill tree, both manifests, both
  marketplace wrappers, and the README shared-skill list;
- publication invariants for 18 required files, 6 JSON files, 44 Markdown
  files, manifest version agreement, exact hook shapes, documented hook
  commands, links, frontmatter, reference discovery, and packaged Skill layout;
- fifteen static routing contracts, ten rollback gates, JSON and YAML parsing,
  English-only public definitions, instruction-size limits, whitespace, and
  absence of private or generated artifacts;
- all six packaged Skills with the local Skill Creator quick validator;
- a focused compaction regression scenario covering a superseded early
  proposal, a later controlling decision, partial raw-output evidence, and the
  current-run versus later-run activation boundary; and
- strict Claude Code plugin validation.

The bundled local `plugin-creator` validator rejects the Codex manifest's
intentional `hooks` field even though Axiom's checked-in wrapper and publication
validator require it. This remains a validator discrepancy, not a pass.

The static scenarios validate checked-in contracts. A fresh Codex or Claude
Code session-level semantic-routing check was not run and is not implied by the
repository checks.

## Known limits

- Review completeness still depends on the history, summaries, tool results,
  and task-inspection interfaces exposed by the active host.
- Compaction cannot recreate unavailable original tool output or hidden model
  reasoning.
- Static construction proves reference discovery and contract presence, not
  semantic model selection in a fresh host session.
- Existing installations and sessions may retain `0.5.0` until the user
  explicitly refreshes and starts a new session.
- The moving `latest` tag is a convenience alias, not an immutable source
  identity.
