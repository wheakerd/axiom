# Axiom v0.16.0

Version `0.16.0` makes `delegate-simple-task` and `continuous-progress` available in Claude Code and renames `optimize-codex-usage` to the host-neutral `optimize-agent-usage`, so every bundled route runs in both hosts. It also extends repository skill maintenance and the routing evaluation contracts to Claude Code. It is a new-capability installed-runtime change; the [runtime identity](../runtime-identity.md) owns its digest and policy revision.

## Host-Neutral Delegation Gate

`delegate-simple-task` keeps its three activation conditions: the active `using-axiom` gate, the host's verified top reasoning level, and invocation consent. The [host evidence reference](../../plugin/skills/delegate-simple-task/references/host-evidence.md) describes each condition without binding it to a particular host setting; the model in the current host judges which of its signals satisfies it.

A permission-bypass mode is one that skips permission prompts. A mode that still reviews, classifies, or denies actions remains ordinary permission. Unknown evidence keeps the skill inactive, and the skill never changes the reasoning setting, permission mode, or subagent configuration to create eligibility.

`using-axiom`, `delegate-simple-task`, and `continuous-progress` no longer set the Codex implicit-invocation parameter. Each skill's description states its explicit-request condition, and the model in either host applies it; the startup Hook still loads `using-axiom` at session start.

## Supervision Across Claude Code Sessions

`continuous-progress` now selects the current host's operations reference: [Codex operations](../../plugin/skills/continuous-progress/references/codex-operations.md) or [Claude Code operations](../../plugin/skills/continuous-progress/references/claude-code-operations.md). The Claude Code reference binds fresh `claude -p` workers, background sessions under the local supervisor, cross-session messaging, compaction hooks, and cancellation.

Session-scoped `CronCreate` tasks and `/loop` are not independent supervisors. A Desktop scheduled task, a cloud scheduled task, or a GitHub Actions schedule can supply the independent wake mechanism within its documented limits. When none is available, the run waits for that capability and reports that automatic recovery is unavailable.

## Repository Skills In Claude Code

[`agents-architect`](../../plugin/skills/agents-architect/SKILL.md) now places a repository skill where the target repository's host discovers it: `.agents/skills/` for Codex and `.claude/skills/` for Claude Code. A repository that uses both hosts keeps one skill body in the shared `.agents/` directory, beside its AGENTS documents. Its Claude Code entry is a symlink to that body or, where the repository's platforms lack symlink support, a pointer that repeats the name and description. The workflow asks before moving an existing `.claude/skills/` body and never creates or edits `CLAUDE.md`, other `.claude/` content, or `.codex/` configuration.

Its inventory audit also models Claude Code instruction loading beside the Codex model: `CLAUDE.md` files load at session start, `AGENTS.md` loads by default when no `CLAUDE.md` exists, subdirectory files load on demand, and `/context` lists what loaded.

## Usage Route Rename

[`optimize-agent-usage`](../../plugin/skills/optimize-agent-usage/SKILL.md) replaces `optimize-codex-usage` with the same measurement boundary, safety rules, and audit reference. Its guidance names no host-specific mechanism: it uses exact usage metrics only when the current host exposes them and labels every other count as a proxy.

To migrate:

- Invoke `$optimize-agent-usage` in Codex or `/axiom:optimize-agent-usage` in Claude Code where you invoked the old name.
- Rename any host setting or permission rule that names `axiom:optimize-codex-usage` to `axiom:optimize-agent-usage`.

## Routing Evaluation For Both Hosts

The routing evaluation contract advances to [schema v5](../../evals/schema-v5.json) and response schema V6. Schema v5 keeps the v4 cases, renames the usage route, drops host names from two usage requests and one goals control, states explicit invocations in plain language instead of Codex's `$skill-name` form, and replaces the delegation request's OpenAI model IDs with a host-neutral ordered candidate list. The `codex-core-v5` and `claude-code-core-v5` profiles select the same ordered cases with the same developer instruction, and each keeps its own host's invocation method, model, effort, timeout, and permission settings. A [Claude Code observer contract](../../evals/claude-code-stream-json-observer-v1.json) defines how a `stream-json` run yields the fixed observer facts, and a [Claude Code review suite](../../evals/review-sequences-claude-code-v1.json) runs the same sanitized review cases. The v4 corpus, its benchmark, and response schema V5 stay immutable, and their records remain verifiable.

## Startup Preamble And Update Reference

The [Claude Code startup hook](../../plugin/hooks/claude-hooks.json) no longer names an unavailable route before reading the same `using-axiom` gate, and the [hook reference](../reference/hooks.md) owns the exact command. Both startup Hooks also run when a session is forked, so a forked session in either host receives the gate. Compatibility records for this release use [evidence schema v4](../../evidence/schema-v4.json), which records each host's declared `SessionStart` sources, and the routing-context record uses [context-budget schema v2](../../evals/context-budget/schema-v2.json), whose lifecycle matrix adds a forked session. The hook still writes nothing, uses no network, and starts no background process. The explicit [update reference](../../plugin/skills/using-axiom/references/updating.md) now covers Claude Code marketplace and plugin updates.

## Evidence Boundary

This local version note claims no publication or installed-host observation. Shared Skill text changed, so Codex reads host-neutral wording for the delegation gate, supervision references, and usage route; its activation conditions are unchanged. [`agent-plugin-architect`](../../plugin/skills/agent-plugin-architect/SKILL.md) no longer treats Codex as the first-class target and prefers each host's native metadata and behavior. The [release status](../../evidence/release-status.json) keeps pending immutable binding and unobserved Codex and Claude Code host fields. Apart from the usage route migration above and reviewing the updated Hook before it runs (in Codex through `/hooks`, in Claude Code before the plugin loads in a new or reloaded session), users need no installation or configuration migration.

The startup gate grows by 160 bytes over `0.15.0`. Its description states its explicit-invocation condition, its lifecycle rule treats a fork as a resume, its `delegate-simple-task` entry names the host's top reasoning level and a permission-bypass mode, and its usage entry names credits, tokens, and context. The fixed routing corpus remains unchanged; this version records no reduction experiment. Counts below are static proxies, not billed tokens or observed lifecycle behavior.
