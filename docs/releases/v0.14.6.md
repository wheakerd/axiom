# Axiom v0.14.6

Version `0.14.6` hardens the explicitly selected simple Git submission phase and corrects secondary routing, target validation, and Skill discovery guidance. It is a compatible installed-runtime change; the [runtime identity](../runtime-identity.md) owns its digest and policy revision.

## Direct Git Configuration Boundary

The [direct submission owner](../../plugin/skills/traceable-git-submit/references/direct-submit.md) checks effective configuration in the requested repository and execution environment immediately before every direct push, including push-only requests. Combined requests also check before the commit; the pre-push check detects drift. It stops on automatic tag following, nonempty effective push options, submodule-pushing recursion or remote mirroring. `push.recurseSubmodules` and `submodule.recurse` are evaluated jointly in Git's configuration traversal order for the executing environment. The last entry of either key decides: `submodule.recurse=true` selects `on-demand`, while `false` selects `no`. Final `on-demand` or `only` stops; `no` and `check` are safe only when they remain final. Git boolean parsing, ordered empty resets, and absent defaults remain distinct from malformed or unreadable evidence.

At both inspections, source-only refspec mapping follows the executing Git version's effective rules, including the first matching `remote.<name>.push` refspec and applicable `push.default=upstream` with branch remote/merge configuration. A mapped leading `+` or destination different from the frozen branch stops. A `remotes.<name>` remote group also stops, including one that shadows a configured remote of the same name; its members are never invoked.

Both inspections also stop on a nonempty inherited `GIT_NAMESPACE` or unclassifiable propagation to the receiving side; it is never cleared or overridden. The list is not exhaustive: any other effective setting or inherited environment that changes the exact command's refs, destinations, remotes, force, tags, submodules, or push options is also a conflict and stops.

A conflict does not authorize flags, configuration edits, another workflow, or a retry. The exact named-remote command, normal hooks, signing policy, endpoint privacy, and one-attempt boundary remain in force. Reports retain only the conflicting key and effect category, never option payloads or endpoint values. Ordinary Git remains host-native; explicit simple submission loads only its direct owner, while hardened submission retains its own phase.

## Target Contracts And Discovery

Where no evaluator or context framework exists, proportional manual/static review and an actual startup surface's byte comparison suffice for that limited evidence. Missing target-required evidence remains incomplete or `NOT-RUN`; no tooling, threshold, or startup surface is invented.

Ordinary routed `.agents/` rules require an explicit next hop. Repo-local Skills, including nested topics, may be discovered as native metadata; this does not prove AGENTS chain loading, Skill body loading, or semantic selection. A declared AGENTS front door still governs. Standalone Skills need no invented AGENTS selector; declared routes still require reachability checks. Protected packaged metadata and the AGENTS native-file write boundary are preserved.
