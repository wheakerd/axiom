# Axiom v0.8.3

Status: unreleased Issue #35 candidate

Version `0.8.3` is a compatible patch for
[Issue #35](https://github.com/wheakerd/axiom/issues/35). It permits one
verified non-force push when the live remote commit is a local ancestor of the
final branch commit, even if the local remote-tracking ref is stale. The live
remote commit owns the direct-push baseline; local tracking state remains
informational and never grants push authority.

Both manifests are synchronized at `0.8.3`. The route name, authorization,
checkpoint, consolidation, recovery, raw-target, hook, and force policies are
unchanged. Issue #37 continues to own the broader host-native direct-push and
transport-simplification request.

## Direct-Push Boundary

The bounded path requires one configured target and exact branch ref, a clear
operation state, and an immediate live remote OID. That OID must exist locally
as a commit and be an ancestor of the final local commit. Identity, target,
operation state, and the same live OID are rechecked immediately before one
non-force push; completion requires the live remote ref to equal the final
commit.

A stale tracking ref alone does not require fetch or a separate tracking-ref
update. Missing or unreadable live state, a non-local or non-commit object,
divergence, force, multiple targets, identity drift, changed live state, push
failure, or ambiguous verification still stops without retry.

The appended schema-v2 routing case expects only `traceable-git-submit`,
forbids `confirm-external-action`, grants no mutation authority, and belongs to
neither frozen benchmark. A deterministic local bare-remote test covers the
reported A/B/C behavior without contacting an external service.
