# Axiom v0.8.3

Status: unreleased candidate history

Version `0.8.3` is a compatible evidence successor for
[Issue #34](https://github.com/wheakerd/axiom/issues/34). It keeps the v0.8.2
routing wording, shared Skill tree, hooks, wrappers, corpus, benchmarks, and
schemas unchanged. Signed candidate commit
`ca9ae1803a806042866b0c4d288791f0f32df8f1` was never tagged or released;
the active successor returns to a truthful v0.8.2 repair rather than skipping
the failed version.

## Preserved Failure And Independent Diagnostic

The release-bound Codex batch against exact v0.8.2 remains terminal `FAIL`.
It stopped at Case 1 after unexpected tool use, made no retry, and left Cases
2-17 `NOT-RUN`. Version v0.8.2 remains unreleased, and this successor does not
rewrite, relabel, or convert that outcome.

One later independent Case 1 diagnostic against the same v0.8.2 commit used
Codex CLI `0.149.1`, `gpt-5.4`, medium reasoning, and a corrected standalone
preflight with permission profile `:read-only`. Its `repeatCount` was one and
its call count was one. The response passed V3 structure and acceptance,
observed `agent-plugin-architect`, requested zero clarification, and returned
false mutation fields. The observer recorded zero tool events, zero unique
tool calls, and unchanged source, installed-plugin, and workspace snapshots.

That diagnostic used 12,278 input tokens, including 1,920 cached input tokens,
69 output tokens, and 13,139 milliseconds. Standard read-only sandboxing does
not prove selective local-read isolation; the diagnostic accepted that stated
limitation and retained no raw response, tool arguments, credentials, or
session artifacts.

The failed release batch and passing independent diagnostic are separate
one-sample observations. Their different Case 1 outcomes are observed
variance, not retries, a pass rate, or proof that tool-enabled behavior is
stable. The diagnostic is not a schema-v2 result, not v0.8.3 host evidence,
and not Stage 3 acceptance.
