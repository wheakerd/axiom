# Axiom v0.7.12

Released: 2026-08-23

Version `0.7.12` closes Stage 1 of
[Issue #32](https://github.com/wheakerd/axiom/issues/32) by accepting the
[`agent-plugin-architect` route contract](../agent-plugin-architect-route-contract.md).
This is a design and release-bookkeeping patch only. It does not install the
route, change current route selection, or claim host behavior for a capability
that is not present.

The immutable Git tag `v0.7.12` will identify this release. Consumers that need
a stable source identity should use that tag rather than a moving alias or
floating branch.

## Stage 1 Decision

The accepted contract freezes:

- the future Skill's canonical English name and description;
- ownership boundaries against repository-local instruction architecture,
  usage optimization, retrospective review, external actions, Git submission,
  persistent installation, and ordinary no-route source work;
- stable positive, paraphrased, near-miss, no-route, multilingual, overlap,
  ambiguity, untrusted-data, and post-compaction expectations;
- a maximum of two simultaneous routes and phase re-routing for architecture,
  Git, installation, and publication work;
- minimum completion evidence, the exact planned v0.8.0 ownership surfaces,
  successor schema and benchmark inheritance, and stop conditions; and
- a static context projection that remains distinct from measured final
  content and exact host usage.

The status is **accepted for Stage 2, not implemented**. Stage 2 is intended
for v0.8.0 because adding a new public route changes installed capability and
requires a SemVer minor release.

## Routing Context Boundary

The public [v0.7.12 routing-context record](../../evals/context-budget/results/v0.7.12.json)
preserves immutable v0.7.9 as the cumulative baseline. The current gate remains
5,899 UTF-8 bytes, 757 whitespace-delimited words, 107 logical lines, one
direct reference, and SHA-256
`1380155863715c28b91223823f3eaadb96bcefbe2482b444ef9dc8e8b62fe011`.
The 1,475 `ceil(bytes / 4)` value is a comparison estimate, not exact host
tokens or credits.

All seven Codex lifecycle and exact-usage observations are `NOT-RUN`.
Authenticated Claude Code lifecycle and exact-usage observations are
`UNAVAILABLE / NOT-RUN` because no subscription or authenticated session is
available. The accepted contract itself has no host observation because its
route is not implemented.

The design document separately projects the canonical Stage 2 gate summary at
6,150 bytes, 788 words, 111 lines, one reference, and an estimated 1,538
tokens. That +251-byte, approximately 425-basis-point projection is below both
current growth-review triggers, but it is only a static design proxy. The
v0.8.0 implementation must measure its actual final content and prove routing
quality independently.

## Release Validation

Candidate validation runs from disposable copies outside the publishable
worktree. It covers the complete standard-library suite, distribution drift,
compatibility evidence and negative controls, routing-context reproduction,
aggregate publication policy, duplicate-aware JSON parsing, Markdown links,
English-only documentation, package shape and direct Skill count, file modes,
whitespace, documentation and brand invariants, and assertions that forbidden
runtime, routing, workflow, model, reasoning, telemetry, and dependency
surfaces remain unchanged.

All 60 standard-library tests passed. Distribution drift passed with seven
shared Skills. Compatibility evidence passed with two records and ten negative
fixtures, and the routing-context check passed all seven lifecycle scenarios
without claiming exact host usage. Aggregate publication policy passed with 54
required files, six policy JSON files, 75 Markdown files, 30 offline route
contract fixtures, 47 black-box routing cases, 13 fixed benchmark cases, nine
host result records, 17 validator parser fixtures, 21 manifest schema fixtures,
and its remaining Git, action, rollback, hook, pull-request, provenance,
CODEOWNERS, and packaged-Skill gates.

The separate duplicate-aware scan parsed 27 JSON files and 47 JSONL records.
All 175 checked local links across 75 Markdown files resolved; the English-only,
seven-direct-Skill package shape, mode `100644`, whitespace, final-newline,
documentation and brand checks passed. The exact 11-path comparison proved
that both manifests changed only their version, historical schemas, benchmarks,
results, and context records remained byte-identical, and every forbidden
runtime, routing, wrapper, workflow, validation, and test surface was unchanged.

Claude Code `2.1.220` strict offline package validation passed in an isolated
configuration directory. It is not authenticated host behavior. The bundled
local `plugin-creator` preserved its known stale non-pass by rejecting Axiom's
intentional `hooks`, `interface.brandColorDark`, and `interface.supportURL`
fields. That diagnostic is not converted into a pass or used to remove currently
supported fields.

## Known Limits

- No Codex host session, model call, marketplace preview, or portal submission
  is claimed for v0.7.12.
- No installed host can select the future route from this release.
- Offline package checks do not prove authenticated Claude Code lifecycle or
  routing behavior.
- The checked-in status cannot embed its own future release commit and remains
  `STATIC-ONLY`.
- No merged-`main`, pull-request, immutable-tag, GitHub Release, or Issue-close
  event is claimed by the local candidate.
