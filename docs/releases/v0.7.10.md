# Axiom v0.7.10

Released: 2026-08-23

Version `0.7.10` closes the always-loaded routing-budget gap described in
[Issue #30](https://github.com/wheakerd/axiom/issues/30). It adds deterministic
repository measurement and evidence without changing the routing gate,
lifecycle hooks, model, reasoning effort, route behavior, action authority, or
installed runtime dependencies.

The immutable Git tag `v0.7.10` will identify this release. Consumers that need
a stable source identity should use that tag rather than a moving alias or
floating branch.

## Lifecycle And Duplicate Detection

The record contains seven ordered scenarios:

1. fresh startup followed by a no-route request;
2. fresh startup followed by a canonical routed request;
3. resume followed by a no-route request;
4. clear followed by a routed request;
5. manual compaction followed by a no-route request;
6. automatic compaction followed by a routed request; and
7. three repeated no-route requests in one otherwise unchanged session.

Each expected count is derived from the checked-in `SessionStart` matcher and
is labeled as a hook-contract expectation, not a host observation. A recorded
host run carries individual injection events and an observed count. The
validator derives duplicate state as observed count greater than expected and
rejects a passing result with a missing or duplicate injection.

No live Codex lifecycle session or model call was performed, so all seven Codex
scenario observations and exact usage fields are `NOT-RUN`. No authenticated
Claude Code subscription or session was available; all Claude Code lifecycle
and exact-usage observations are `UNAVAILABLE / NOT-RUN`.

## Growth And Reduction Policy

The v0.7.9 gate is the cumulative baseline. Growth of at least 256 UTF-8 bytes
or 5% requires explicit review and a substantive justification. That threshold
is a review trigger only: it does not replace routing, safety, authorization,
or evidence acceptance and does not automatically reject a justified change.
The absolute branch remains meaningful for an already sizable gate, the
relative branch scales to smaller gates, and cumulative comparison prevents
successive sub-threshold increases from resetting the baseline.

Any actual reduction must attach equivalent before/after `PASS` results for
both routed and no-route cases over the exact same fixed routing workload.
Static contract validation and host observation remain distinct evidence
classes. This release makes no reduction claim and does not move routing or
safety detail merely to manufacture a saving.

## Release Validation

The candidate is validated from a disposable copy outside the publishable
worktree. The local workflow covers:

- exact proxy reproduction for the default gate and an alternate UTF-8 input;
- legitimate unchanged, below-threshold, absolute-threshold, relative-threshold,
  duplicate-injection, and missing-reduction-evidence controls;
- all seven lifecycle records, fixed corpus identity, routed/no-route coverage,
  and preservation of the complete routing benchmark and historical results;
- distribution drift, compatibility evidence, publication policy, JSON,
  Markdown links, English-only documentation, package shape, and whitespace;
- the complete standard-library unit-test suite and repository-relative
  invocation; and
- direct diff review of every measurement, evidence, validation, manifest,
  documentation, and release surface.

The local checks do not claim a GitHub pull-request run, merged-`main` run,
immutable-tag run, GitHub Release event, Codex lifecycle observation, or Claude
Code authenticated host observation. Those remain `NOT-RUN` or `UNAVAILABLE`
until a separately authorized phase directly observes them.

All 54 standard-library unit tests passed. The aggregate passed with 52
required files, 72 Markdown files, 47 routing cases, 13 fixed benchmark cases,
nine preserved host result records, and seven routing-context lifecycle
scenarios at version `0.7.10`. Repository-relative context measurement,
distribution drift, compatibility evidence, JSON parsing, English-only
documentation, package shape, and whitespace checks also passed.

Claude Code `2.1.220` strict marketplace and plugin validation passed in an
isolated configuration directory. This is an offline package signal, not an
authenticated host or lifecycle observation. Codex CLI `0.149.0` exposes no
plugin-validation subcommand. The bundled local `plugin-creator` validator
continues to reject the Codex manifest's intentional `hooks` field; that known
validator conflict remains an explicit non-pass rather than a reason to remove
the declared hook.
