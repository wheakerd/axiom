# Axiom v0.25.0

Version `0.25.0` makes the host permission boundary take effect where it mattered: under a host mode that decides each call without a native prompt, the two action owners present the exact command and target as visible text and obtain the grant before the first irreversible step. The startup gate now requires a visible notice whenever it selects or hands off a route and sets the output language of Axiom-guided turns. The release records a private audit of route selection on the maintainer's machine, kept as categories and counts, as the measured starting point for Issue #240.

## Why A Minor

The [release standard](../runtime-identity.md#version-increment) assigns a minor increment to a new protocol. The invocation notice was an optional convention and becomes part of the gate's "No silent pick, no silent route" invariant; the Output Language rule is a new gate behavior. No route is added or removed, and no description changes.

## What Changed

- Pre-attempt grant (Issue #239): the Authorize phase of `confirm-external-action` and the Authority Boundary of `reversible-system-change` state that, where a host mode decides each call without a native prompt, the exact command and target are presented as visible text and granted before the first attempt, and that the no-redundant-confirmation default applies only with a native prompt. `using-axiom/references/host-permission.md` scopes its last bullet the same way, says a thinking block or tool-call line is not a notice, requires one mutation per tool request, and orders a multi-step irreversible sequence so that a denial between steps leaves a recoverable state. `reversible-system-change` carries the ordering rule in its Change Contract and `preflight-and-rollback.md`, and the one-mutation rule in `execution-and-verification.md`. The gate's authorization sentence and its denial invariant say "with a native prompt" and "as visible text". The validator anchors pin the new wording in both owners.
- Route-sunk detail: `confirm-external-action/references/action-envelope.md` holds the envelope field list and the bulk-action rules, with the entry keeping a summary that names every field; `reversible-system-change/references/rollback-point.md` holds the rollback-point contract split out of `preflight-and-rollback.md`, including the isolated-restore-rehearsal boundary that the entry's phase bullet used to state inline. No rule was removed; the maintainer's principle is the minimum effective description, never a smaller file.
- Host facts: `claude-code-host.md` records the 2026-11-02 observation on Claude Code 2.1.309 beside the 2.1.308 facts.
- Visible notice (Issue #241): invariant 5 of the gate reads "No silent pick, no silent route" and adds that routing never selects or hands off a route without a visible text notice naming it; the Invocation Notes section names the format (`Axiom:<skill-name>`, `<plugin>:<skill-name>`, or the tool's own name, with a brief reason) and excludes thinking blocks, tool-call lines, startup, and no-match. The validator pins the invariant and the exclusion.
- Output language (Issue #242): the gate's Output Language section keeps working output English unless the user asks otherwise and writes the final conclusion or summary of a turn in the language of the request; the README example, [Architecture](../architecture.md), [Examples](../examples.md#notices-and-language), and the [Trust Model](../trust-model.md#authority-across-workflows) describe both rules.
- Gate size: the gate grows from 7,217 to 7,370 bytes within its 7,372-byte publication maximum. The "No match" item no longer repeats the pinned "No match continues host-native" sentence, the "Routing stays read-only" sentence that restated invariant 1 is gone, and the host-facts pointer is kept in a shorter form.

## Private Audit Behind Issue #240

A private audit of 25 Claude Code sessions on the maintainer's machine with the gate delivered (595 user turns) and 2 Codex sessions (4 turns), retained only as categories and counts, found 24 turns that selected a bundled route (27 selections). Judged against the descriptions, 10 selections were correct and 17 were not needed, most on `local-web-search` fired without a research request and on `reversible-system-change` fired on ordinary edits. Thirteen requests that matched a description selected no route: five explicit delegation requests, three deployments or cleanups with explicit authority, two Axiom task reviews, two AGENTS updates, and one page open in the user's own browser; recall on clear cases was 10 of 23. Seven misses were borderline. The classification and candidate actions live in the Issue; this release changes no description, and any wording change is decided by a two-arm fresh-session measurement on both hosts.

## Routing Contract

Routing contract v8 and its two host benchmark profiles are unchanged: no case is added or retired in this release, and the gate's selection rules and every description keep their text. Because the gate changed, the release gate requires fresh-session observation records for every route on both hosts under `evals/results/v0.25.0/`, bound to this runtime digest.

## Unchanged Boundaries

Routing still selects instructions only. The notice grants nothing, and the grant presented under a per-call mode is what the host then evaluates, not a way around its decision. `delegate-simple-task` consent, the external-action authorization gate, the rollback evidence gate and its informed waiver, untrusted-input handling, and every other stop condition stay hard.
