# Axiom v0.4.1

Released: 2026-08-12

Version `0.4.1` improves how AGENTS Architect learns from completed task
evidence. Repeated source inspection can now prompt a scoped instruction-gap
review without turning file counts, task duration, or context compaction into
automatic proof that AGENTS guidance is incomplete.

The immutable Git tag `v0.4.1` identifies this release. The moving `latest`
Git tag and GitHub's Latest Release marker are synchronized to the same release
commit; consumers that need a stable identity should use `v0.4.1`.

## Highlights

### Retrieval-friction review

AGENTS Architect now reviews what a task had to read during routing,
live-source discovery, contract recovery, and validation. Repeated source
reopening, Git or task-history recovery of stable policy, user corrections,
and unrelated sibling scans caused by a missing route are candidate signals,
not automatic durable updates.

For each signal, the workflow records the needed fact, its existing or missing
owner, the smallest rule, route, source-of-truth pointer, or validation step
that could reduce rediscovery, and the live-source checks that remain required.

### Explicit dispositions

Retrieval-friction evidence is classified as `instruction-gap`, `routing-gap`,
`validation-gap`, `expected-live-verification`, or `one-off-code-defect` before
maintenance is proposed. Instruction, routing, and validation gaps receive the
smallest matching owner update. Expected live verification remains required,
while one-off defects stay in source or regression tests under separate
authorization unless further evidence establishes a reusable project rule.

### Effective instruction integration

Both `effective-instructions` and `effective-instructions:preview` apply the
same review. Reports include accepted and rejected candidates plus the source
checks that future work must still perform. The goal is correct routing and
less avoidable rediscovery, not zero source reading.

## Compatibility and package shape

- Both plugin manifests declare version `0.4.1` and point to `./skills/`.
- The direct public Skills remain `using-axiom`, `agents-architect`,
  `optimize-codex-usage`, `traceable-git-submit`, and
  `reversible-system-change`.
- Codex and Claude Code retain separate manifests, marketplace descriptors,
  and hook files over the same Skill source.
- No hook command, startup route, skill identifier, runtime dependency,
  service, telemetry path, or automatic updater was added.

## Release validation

The release candidate was checked from the repository and, for validators that
could write, from a disposable copy outside the publishable tree. The recorded
workflow verified:

- distribution agreement among the Skill tree, both manifests, both
  marketplace wrappers, and the README shared-skill list;
- publication invariants for required files, JSON structure, manifest version
  agreement, exact hook shapes, documented hook commands, Markdown links,
  frontmatter, reference discovery, and packaged Skill layout;
- static routing contracts, rollback gates, JSON and YAML parsing,
  English-only public definitions, instruction-size limits, whitespace, and
  absence of private or generated artifacts;
- all five packaged Skills with the local Skill Creator quick validator;
- strict Claude Code `2.1.220` plugin validation; and
- two read-only forward scenarios covering a durable instruction conflict and
  a one-off named-parameter defect.

Codex CLI `0.147.0` does not expose a plugin-validation command. The bundled
local `plugin-creator` validator rejects the Codex manifest's intentional
`hooks` field even though Axiom's checked-in wrapper and publication validator
require it. This remains a validator discrepancy, not a pass.

The forward scenarios exercise the checked-in decision contract. They do not
prove that every fresh host model will make the same semantic classification.

## Known limits

- Reading many files does not by itself prove that AGENTS guidance is missing.
- Mutable source, diffs, runtime state, and concrete change impact still
  require current direct inspection.
- Existing installations and sessions may retain `0.4.0` until the user
  explicitly refreshes and starts a new session.
- Axiom cannot turn an unavailable validator or unobserved downstream behavior
  into a pass.
- The moving `latest` tag is a convenience alias, not an immutable source
  identity.
