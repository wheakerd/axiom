# Axiom v0.27.1

Version `0.27.1` fixes five defects in `traceable-git-submit` that an independent read-only review of the 0.27.0 tree found and the maintainer verified against the skill text and Git's documented behavior (Issue #259). The skill's description, the startup gate, every other skill, and the hooks are unchanged.

## Why A Patch

The [release standard](../runtime-identity.md#version-increment) assigns a patch increment to a fix without new capability. Every change below corrects a procedure the skill already claimed to perform or makes an existing rule executable; no route, trigger, or selection surface changes.

## What Changed

- Commits run the repository's hooks. The checkpoint, consolidation, and prepared-release phases create their commits with ordinary `git commit` from the frozen, verified index, so `pre-commit` and `commit-msg` run; invariant 2 and the [Trust Model](../trust-model.md#authority-across-workflows) had stated this while the phases used `git commit-tree`, which runs no hook. Each commit is proved against the recorded tree and parent immediately after creation, and a failed proof restores the branch by compare-and-swap, so a hook that rewrites the index cannot change what is committed unnoticed.
- Shell-string hosts. `references/git-values.md` required every Git value as an argument-vector element and stopped the phase on a host that runs only a shell string, which made every heavy phase unusable on Claude Code as written. The rule now says how to pass a value safely on such a host: one single-quoted literal with no expansion, with values that contain a single quote, NUL, CR, or LF or begin with `-` rejected before the command, and no `eval`, backticks, or `$()` around a value.
- One command per target. When a remote is configured with several push URLs, heavy pushes run once per URL, so the first failure stops the sequence as invariant 5 requires; a remote with one push URL keeps its remote name. The skill states the two effects of a push named by a configured URL, both verified by the fixture test on Git 2.56: Git resolves the URL to its remote and updates that remote's tracking refs, and `pre-push` receives the URL instead of the remote name. The URL appears only in the command, never in reports or records.
- Tag creation. `git tag` creates the tag ref itself and refuses an existing name, so the create-only `update-ref` step that followed it could never succeed; the step is removed and the verification of the tag object and its peeled commit stays.
- `--no-verify`. Invariant 2 now states that the direct-submit phase never adds it, matching `references/direct-submit.md`.
- Ordinary commits behave as ordinary commits. `commit.gpgSign` is honored where `commit-tree` ignored it, Git's default message cleanup strips trailing whitespace and collapses blank lines, and a `commit-msg` hook that appends a trailer makes the frozen-message proof fail closed; the Changelog names these effects.
- Validators and tests: the traceable-Git contract anchors in `axiom_validation/cases/git_contracts.py` follow the new text, and `tests/test_git_contracts.py` gains deterministic fixtures that execute the changed procedures against a disposable repository: commit hooks run and a failing hook leaves `HEAD` unchanged, the commit carries the recorded tree and parent, a hook that rewrites the index is detected and the branch restored, an empty checkpoint needs `--allow-empty`, the consolidation sequence yields a commit with the upstream parent and the final tree and is restorable, `git tag` refuses an existing name in both modes, a push named by a configured URL updates that remote's tracking refs and hands `pre-push` the URL, and message cleanup is not byte-preserving.

## Routing Contract

Routing contract v8 and both host benchmark profiles keep their 49 cases. No selection surface changed: the startup gate and every skill description are byte-identical to 0.27.0, so under the two-tier gate of repository policy revision 134 this release requires no candidate observation record, and none is checked in. No fresh-session run was made for this release: the maintenance rules exempt a change confined to skill bodies and references, because the host lists only names and descriptions before a skill is selected, and the changed Git procedures are exercised by the deterministic fixture tests named above instead.

## Unchanged Boundaries

Route selection grants no Git action authority. Checkpoints, baseline mutation, consolidation, remote refresh, push, and recovery cleanup still need separate authority; pushes are never retried after an uncertain result; `git reset --hard`, `git stash`, and `git clean` stay prohibited; and ordinary named-remote non-force Git stays host-native.
