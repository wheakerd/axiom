Version `0.8.18` is the release-version safety patch for [Issue #89](https://github.com/wheakerd/axiom/issues/89). It aligns every production publication stage on stable numeric `MAJOR.MINOR.PATCH` versions without rewriting historical tags or Releases.

## Canonical Production Release Grammar

`axiom_validation/release_versions.py` now owns the production-release parser, the Bash tag pattern derived from the same numeric component grammar, and the shared acceptance corpus. Stable versions such as `0.8.18`, `1.0.0`, and `12.34.56` are accepted. Prerelease identifiers, build metadata, leading-zero components, a `v` prefix in a manifest, missing components, and extra components are rejected.

Both plugin manifests, release evidence, GitHub Latest comparison, and attestation subjects use the canonical Python parser. The exact JavaScript signed-target guard and Bash immutable-publication gate are validator-bound to equivalent patterns and the same regression cases.

## Rejection Before Tag Creation

Manual signed-target validation now parses `release/v<version>` with the production grammar and binds the named version to both manifests. A prerelease, build-metadata, leading-zero, malformed, or mismatched candidate therefore fails before a formal upstream `v*` tag is created. Main, tag-push, GitHub Release, and post-publication checks retain the same GitHub-signature and history requirements.

Historical tags and Releases remain unchanged. Supporting prerelease identifiers or build metadata later requires a separately reviewed design for GitHub prerelease state, Latest selection, version precedence, evidence asset naming, recovery, and stable-versus-prerelease compatibility claims.

## Regression Contract

The checked-in corpus exercises the canonical Python parser, exact GitHub Script, candidate-branch binding, formal tag parsing, and Bash publication pattern. Negative cases cover prerelease identifiers, build metadata, their combination, leading-zero major and minor components, prefixed manifest values, missing components, and extra components. A separate mismatch case proves that a correctly shaped candidate branch cannot carry a different manifest version.
