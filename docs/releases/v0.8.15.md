Version `0.8.15` is the security fix-forward release after immutable `v0.8.14`. It closes the Windows startup executable-resolution boundary and binds formal release-tag creation to an exact server-side actor without changing Axiom routes, Skills, action authority, benchmark membership, or runtime dependencies.

## Windows Startup Resolution

The Codex Windows `SessionStart` handler no longer launches an unqualified PowerShell executable from the session working directory. It invokes the fixed plugin-relative `hooks/codex-session-start.cmd` wrapper, which uses only `echo`, `setlocal`, and `type` to print the startup notice and load the shared `skills/using-axiom/SKILL.md` gate. The handler has an explicit five-second timeout and resolves no second interpreter or executable through the working directory or `PATH`.

The POSIX Codex command, Claude Code wrapper, one-handler lifecycle shape, `startup|resume|clear|compact` matcher, shared routing gate, and foreground read-only behavior remain unchanged. The wrapper performs no write, network request, background launch, profile load, updater, or credential access.

## Release-Tag Creation Authorization

The commit-level `Verify GitHub-signed release target` result remains defense-in-depth target evidence, but it is no longer treated as authorization for an exact tag-creation operation. Formal upstream `refs/tags/v*` creation is controlled by the separate active `restrict-release-tag-creation` ruleset. Its only rule is `creation`, and its only bypass actor is the repository owner `wheakerd` in `always` mode.

The active `require-github-signed-release-tags` integrity ruleset retains required signatures, the required check, deletion prevention, and non-fast-forward prevention with no bypass actors. The actor bypass is scoped only to the creation-only ruleset, so the permitted creator must still satisfy every integrity rule. Forks, contributor branches, pull requests, CI, reviews, and tags created inside contributor forks are unaffected; repository write access alone does not grant formal release-tag authority.

## Regression Contract

The hook validator now requires the exact plugin-relative command, exact regular non-symbolic wrapper bytes, one handler, the complete lifecycle matcher, and the five-second timeout. Negative fixtures reject the earlier PowerShell form, alternate unqualified or relative PowerShell and `pwsh` spellings, and the former unbounded timeout. The Windows-only focused test reproduces Codex's literal outer-quote `cmd.exe /C` spawn form from a working directory containing executable canaries and verifies the expected startup output.

The repository-governance contract now requires complete scoped assertions inside the `Release Tag Policy` section: an active creation-only ruleset with exactly one creation rule and the sole user bypass, plus an active no-bypass integrity ruleset with no creation rule. Focused negative tests reject both the stale unknown-creator statement and a contradictory inactive or no-creation description that retains the individual policy tokens.
