# Axiom v0.17.0

Version `0.17.0` moves everything a host installs into the `plugin/` subtree: both manifests, the startup Hooks and Codex wrapper, the shared Skills, the Codex interface artwork, and a byte-identical license copy. The marketplace catalogs stay at the repository root. Skills, Hooks, and manifest fields are unchanged inside the plugin root; the [runtime identity](../runtime-identity.md) records their new paths under runtime schema v4 and owns the digest and policy revision.

## Installed Plugin Subtree

Before this version each catalog's `url` source made a host copy the whole repository, including documentation, evaluation records, evidence, tests, and validators that no host loads. The [Codex manifest](../../plugin/.codex-plugin/plugin.json) and the [Claude Code manifest](../../plugin/.claude-plugin/plugin.json) now sit in `plugin/`, and their `./skills/`, `./hooks/`, and `./assets/` paths resolve inside that subtree. The Hook commands still read `skills/using-axiom/SKILL.md` from the installed plugin root, so the installed definitions keep their text.

## Catalog Migration

The [Codex catalog](../../.agents/plugins/marketplace.json) and the [Claude Code catalog](../../.claude-plugin/marketplace.json) keep selecting `v0.16.0` through the `url` source until `v0.17.0` is the verified immutable Latest release. The marketplace-publication pull request then switches both catalogs to a `git-subdir` source for the same repository and tag, with `path` set to `./plugin` for Codex and `plugin` for Claude Code, as the [release guide](../maintainers/release-documentation.md#marketplace-publication) describes. Validators require that form for `v0.17.0` and later tags and the `url` form for earlier tags.

Users update with the usual commands: in Codex, refresh the marketplace; in Claude Code, update the marketplace and then the plugin. The host replaces the previous installed copy with the subtree. Review the installed Hook before it runs, as for any update.

## Identity And Validation

The [schema v4 input policy](../../axiom_validation/runtime-contract-inputs-v4.json) treats `plugin/` as the only installed surface root. It includes the same Skill files, Hook files, and manifest fields as schema v3 under their new paths and excludes the license copy and the artwork. Its history starts at `v0.16.0`, which contributes no records because that tag predates the subtree; schema v3 keeps classifying `0.14.6` through `0.16.0`. The routing-context record moves to schema v3 to bind the gate's new path, and the validators resolve each manifest's component paths from its own plugin root. The release-signature guard reads the Codex manifest from its new path, and CODEOWNERS covers the moved critical paths.
