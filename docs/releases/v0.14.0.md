# Axiom v0.14.0

Version `0.14.0` adds the explicitly invoked [Continuous Progress](../../plugin/skills/continuous-progress/SKILL.md) workflow. It coordinates fresh workers and successor coordinators while a separate, addressable native supervisor follows the durable task record.

## Host And Lifecycle Boundary

Activation requires native dispatch, durable state, exclusive coordinator ownership, and a verified independent wake mechanism. Ordinary continuation, skill evaluation, and requests for native Goals alone do not activate it. No daemon, scheduler executable, global hook change, or startup background operation is added to Axiom. The host owns scheduling and permissions.

The protocol distinguishes artifact success from native turn completion and supervisor shutdown. Compaction recovery waits for the host turn to settle, rereads the original goal and constraints, and transfers coordination. Cancellation stops new dispatch, disables the exact schedule, interrupts active turns, and reconciles their command handles and partial effects.

CLI-only execution cannot promise future wakeups without a supported external host scheduler. Local schedules depend on the owning application and machine. Automatic context reserve prediction, offline recovery, and other operating systems require evidence from the selected host; a bounded lifecycle drill does not establish universal survival or long-task quality.

## Routing And Compatibility

The startup gate retains its foreground, read-only behavior and adds one explicit-only route. The twelve-route corpus uses schema v4 and response V5; the earlier schemas, corpora, benchmarks, and observations retain their original contracts. Existing users need no migration.

The candidate's release status remains `STATIC-ONLY` and its immutable tag binding remains pending. Native package parsing, installation, and lifecycle claims remain distinct; no publication or installed-host result is inferred.
