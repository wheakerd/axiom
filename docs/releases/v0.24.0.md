# Axiom v0.24.0

Version `0.24.0` rewrites the fourteen bundled skills for a model reader. Each skill now opens with a short direction paragraph and an Invariants section of three to six named rules that bind in every phase; everything else in the skill is a default the model may adapt, saying so. The startup gate defines the shared terms once, describes explicit invocation in each host's own syntax, and owns two dated host references; `agents-architect` reconcile modes run in one session; and the publication aggregate checks the new readability contract.

## Why A Minor

The [release standard](../runtime-identity.md#version-increment) assigns a minor increment to a changed protocol. The reconcile modes of `agents-architect` no longer require a coordinator plus three subagents, the gate replaces its blanket binding clause with named invariants, and `continuous-progress` reads the gate's host references instead of its own two operations references. No route is added or removed, and the descriptions change only by one split sentence in `agents-architect`.

## What Changed

- Invariants (Issue #226): every `SKILL.md` lists three to six named invariants under an `## Invariants` heading, introduced by the same sentence: these invariants bind in every phase, including the references that phase loads, and everything else is a default you may adapt, saying so. The "Defaults you may adapt, saying so ... Every other rule ... binds" paragraphs are gone from all twelve skills that carried them, and `agents-architect` folds its Decision Latitude and Always-On Rules into six invariants. Each invariant restates a rule that already bound; no authority widens.
- Terms: the gate defines route, host-native, selection surface, explicit invocation, invariant and default, handoff contract, envelope, and write set once. A skill that introduces a term defines it under `## Terms` where it first appears: material ambiguity in `clarify-intent`; observed, recalled, summarized, and ledger in `verify-completion`; permission-bypass mode and candidate list in `delegate-simple-task`; evidence states and material-effect categories in `review-axiom-task`; coordinator, worker, supervisor, and run record in `continuous-progress`.
- Sentences: no sentence in bundled skill text exceeds 300 characters, measured per paragraph, list item, heading, or frontmatter field with code blocks and tables excluded. Twenty-one over-long sentences in the entry files and references were split without changing their rules.
- Invocation: the gate states explicit invocation as `$skill-name` in Codex, `/axiom:skill-name` in Claude Code, or the skill named in plain words, and the offline route model and its fixtures accept both host forms. The optional `Axiom:<skill-name>` display convention for explaining an invocation is unchanged.
- Host facts: `using-axiom/references/codex-host.md` and `using-axiom/references/claude-code-host.md` consolidate the host mechanics that were spread over `agents-architect`, `continuous-progress`, `delegate-simple-task`, and the gate's permission reference. Each opens with the host version it was verified against on 2026-10-30 and marks the facts restated from host documentation; both tell the model to consult the host's own help for commands. `continuous-progress` keeps three references instead of five, and its host-neutral supervisor and acceptance rules move into `supervision-and-recovery.md` and `execution-and-handoff.md`.
- Reconcile modes: `agents-architect/references/maintenance/implementation-reconciliation.md` replaces the mandatory coordinator-plus-three-subagents contract with an independent review contract that one session can run as sequential passes, keeping the three independent read-only reviews, the direct recheck of decisive evidence, and the single writer.
- Validation: `axiom_validation/skill_text.py` enforces the Invariants list, the sentence maximum, and the absence of a blanket binding clause in the publication aggregate, with unit tests and a documented check in the validation guide.

## Routing Contract v7

The routing contract, the corpus, and both benchmark profiles are unchanged. Because the gate and every skill body change, the release gate requires fresh-session observation records for every route on both hosts under `evals/results/v0.24.0/`, bound to this runtime digest.

## Host Evidence

The release gate introduced by repository policy revision 118 requires one checked-in fresh-session observation record per host for this release under `evals/results/v0.24.0/`, bound to this runtime digest, before the pipeline publishes. Those records are produced on one machine with the installed plugin on Codex CLI and Claude Code and are added to the release pull request after the runtime inputs are final; they are pre-publication observations, not a publication or installed-host lifecycle observation. A private paraphrase check, in which a fresh model session restates each skill's invariants, is release evidence kept outside the repository.

## Unchanged Boundaries

Routing still selects instructions only. `delegate-simple-task` consent, the external-action authorization gate, the rollback evidence gate and its informed waiver, untrusted-input handling, and every other stop condition stay hard. A delegated choice still settles only under the gate's rule: every alternative reversible and already authorized, the pick and why stated before acting, and no persistent system change, external or remote-state change, deletion, credential use, or material cost authorized by an offered option.
