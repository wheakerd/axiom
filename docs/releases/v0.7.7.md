# Axiom v0.7.7

Released: 2026-08-21

Version `0.7.7` refactors the repository publication validator into focused,
independently testable policy modules. It is a compatible maintenance change
for [Issue #27](https://github.com/wheakerd/axiom/issues/27); it adds no public
Skill and does not change installed routing or action authority.

The immutable Git tag `v0.7.7` will identify this release. Consumers that need
a stable source identity should use that tag rather than a moving alias or
floating branch.

## Highlights

### Policy ownership is explicit

The stable `python3 scripts/check-publication.py` command now delegates to
standard-library modules under `axiom_validation/`. Manifest, hook, Markdown,
strict-YAML, routing, traceable-Git, GitHub Actions, release-provenance,
repository-layout, and reporting policy each have a focused owner.

The aggregate remains repository-relative and preserves its deterministic
single-line success output and exit-code contract. Failure lines now include the
owning policy domain so a manifest failure is distinguishable from a release or
routing failure without reading the aggregate implementation.

### Fixtures and production policy are separate

Deterministic event, parser, authorization, rollback, and mutation fixtures now
live under `tests/fixtures/`. Focused `unittest` modules exercise every major
policy domain independently, including the exact release-workflow JavaScript
and the mutation-bypass regression case. The aggregate reuses those fixtures so
CI and focused tests apply the same acceptance inputs without embedding them in
production policy modules.

### Release identity has one source

The current release version is derived from the synchronized Codex and Claude
Code manifests. Release documents are discovered from `docs/releases/`, so the
validator no longer maintains a second hard-coded release-history list. Invalid
or divergent manifest versions still fail closed through the manifest domain.

## Compatibility and package shape

- Both plugin manifests declare version `0.7.7` and point to `./skills/`.
- The seven direct public Skills, both marketplace wrappers, both platform hook
  definitions, and both GitHub Actions workflows are unchanged.
- The new Python package and tests are contributor and CI infrastructure. They
  introduce no installed daemon, background process, updater, network check,
  credential access, route-selection change, or third-party runtime dependency.
- `evidence/release-status.json` marks v0.7.7 `STATIC-ONLY`. Immutable v0.7.4
  host observations remain prior-release evidence and are not promoted to a
  current v0.7.7 pass.

## Release validation

The candidate was checked from disposable copies outside the publishable tree.
The recorded local workflow verified:

- the aggregate command retained exit code `0`, empty stderr, and the same
  ordered success fields as the v0.7.6 baseline;
- all focused standard-library unit tests passed, including domain-local
  negative fixtures and release mutation detection;
- distribution drift, compatibility evidence, manifest and hook JSON,
  repository links, strict YAML parsing, packaged Skill shape, English-only
  content, and release-version surfaces remained consistent; and
- no `.github/workflows/**` file changed, while the existing three
  pull-request event-graph and nineteen release-provenance fixtures remained
  green.

Five alternating measurements placed the v0.7.6 aggregate baseline between
0.25 and 0.26 seconds, with a 0.26-second median. The final v0.7.7 candidate
ranged from 0.25 to 0.27 seconds, with a 0.25-second median. No material runtime
regression was observed.

The bundled local `plugin-creator` validator still rejects the Codex manifest's
intentional `hooks` field. This remains a known validator discrepancy, not a
pass. Claude Code `2.1.220` strict offline plugin validation passed in an
isolated home directory. Authenticated Claude Code lifecycle validation was
unavailable because the current user has no subscription or authenticated
session; no Claude Code host pass is implied.

## Known limits

- No fresh v0.7.7 Codex `0.149.0` host lifecycle was run. The change affects
  repository validation rather than installed routing, and immutable v0.7.4
  observations remain prior-release evidence only.
- Claude Code startup, compaction, routed, and no-route cases remain
  `UNAVAILABLE`; no subscription or authenticated session was available.
- `actionlint` was unavailable and remains `NOT-RUN`. No workflow file changed,
  and the existing strict parser plus workflow fixtures remained green.
- The pull request, merged-`main` run, immutable-tag run, and GitHub Release run
  are remote publication evidence and are not claimed by local validation.
- The immutable `v0.7.7` tag, not a moving alias, is the stable release
  identity.
