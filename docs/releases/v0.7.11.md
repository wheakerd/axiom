# Axiom v0.7.11

Released: 2026-08-23

Version `0.7.11` closes the Codex marketplace presentation gap described in
[Issue #31](https://github.com/wheakerd/axiom/issues/31). It adds supported
listing metadata and a repository-owned visual mark without changing Axiom's
Skills, routing gate, lifecycle hooks, action authority, model, reasoning
effort, telemetry boundary, or installed runtime dependencies.

The immutable Git tag `v0.7.11` will identify this release. Consumers that need
a stable source identity should use that tag rather than a moving alias or
floating branch.

## Codex Listing Contract

The Codex manifest now declares:

| Field | Value |
| --- | --- |
| `shortDescription` | `Guardrails for agent actions` |
| `websiteURL` | `https://github.com/wheakerd/axiom#readme` |
| `supportURL` | `https://github.com/wheakerd/axiom/issues` |
| `brandColor` | `#111827` |
| `brandColorDark` | `#5EEAD4` |
| `composerIcon` | `./assets/axiom-mark.svg` |
| `logo` | `./assets/axiom-mark.svg` |

The listing exposes exactly three single-line, non-mutating starter prompts:

1. `Audit this repository's AGENTS.md instruction system. Report findings only.`
2. `Plan a reversible production change with rollback evidence. Do not execute it.`
3. `Review the routing, authorization, actions, and evidence for this Axiom-guided task.`

The same font-free square SVG is used for both image fields. Its four-node graph
is derived from Axiom's existing social-preview artwork and remains owned by
this repository. It has explicit 512-by-512 intrinsic and view-box dimensions,
contains no scripts or external content, and adds no image-generation or
runtime dependency.

Axiom is a skills-only plugin without MCP custom UI. The Codex manifest
therefore omits `interface.screenshots`; no screenshot or synthetic success
state was generated. It also omits undocumented or unowned presentation fields
such as `logoDark`.

## Fail-Closed Validation

The standard-library manifest policy now validates the closed supported field
set and the checked-in Axiom values. It rejects:

- non-HTTPS or credential-bearing listing URLs and values over 1,024
  characters;
- invalid six-digit brand colors or contrast below 2:1 against the documented
  light and dark directory backgrounds;
- empty, multiline, overlong, duplicate, or app-mention starter prompts, plus
  lists containing more than three entries;
- asset paths outside the plugin, traversal, symlinks, directories, missing
  files, and unsupported extensions;
- image files larger than 5 MiB, non-square or sub-48-pixel dimensions, and
  raster dimensions over 4,096 pixels; and
- malformed or unsafe SVG content, including nonnumeric dimensions, DTDs,
  entities, scripts, event handlers, style metadata, foreign namespaces, and
  active or external references.

The validator handles supported PNG, JPEG, WebP, and SVG paths without adding a
third-party runtime dependency. Negative fixtures cover the listing contract,
and focused tests exercise supported formats plus unsafe and unusable assets.
