Version `0.8.12` is the patch release for [Issue #62](https://github.com/wheakerd/axiom/issues/62). It completes Axiom's validator modularization without changing routing, authorization, release, or evidence semantics.

## Production-Owned Validation Cases

The aggregate publication validator no longer imports executable fixtures from `tests`. Canonical action-graph, external-action, traceable-Git, hook, manifest, parser, release, rollback, and routing cases now have one dependency-free source of truth under `axiom_validation.cases`; focused unit tests import the same production-owned cases. `tests/fixtures` retains only test-specific routing-evaluation mutation builders.

An isolation regression runs the aggregate validator in an isolated interpreter that rejects every `tests` import and requires the complete success summary. A separate static import audit rejects any future production dependency on the repository test package.

## Focused Routing Evaluation Modules

The former 132 KiB `axiom_validation/routing_evals.py` module is replaced by focused modules for constants, strict JSON input, schemas, acceptance, corpus coverage, benchmarks, observer taxonomy, evidence derivation, observations, external post-tag validation, immutable history, and aggregate suite orchestration. The package facade preserves every prior intentional public constant, function, and class import used by scripts and tests.

The split keeps generic validation logic separate from release history and narrows internal imports without adding a third-party runtime dependency. Existing corpus counts, benchmark membership, result counts, response classifications, observation acceptance, failure prefixes, output text, and exit codes remain unchanged.

## Strict Data-Driven History

Immutable run IDs, result paths, schema digests, commits, trees, subjects, terminal classifications, and preserved outcome digests now live in `validation_data/routing-history-v1.json`. Its loader rejects duplicate keys, missing or unknown fields, invalid lowercase IDs, malformed Git OIDs and SHA-256 digests, path escape, duplicate identities, symlinks, oversized sources, and candidate/released subject mismatches.

The checked-in index is protected by a whole-file SHA-256 binding so deletion, reassignment, reordering, or unreviewed historical edits fail closed. Existing historical observation files remain unchanged and continue to satisfy their original immutable digests.

## Local Static Validation

The complete 117-test standard-library suite, aggregate publication guard, distribution drift guard, compatibility self-test, routing-context budget check, canonical-facts check, JSON parsing, Python compilation, English-only scan, Claude Code strict offline package validation, and whitespace checks pass in disposable release copies. The aggregate summary is 75 required files, 6 manifest and hook JSON files, 68 offline route fixtures, 67 black-box routing cases, 30 benchmark cases, and 11 historical host-result records; the new release note increases the repository Markdown count to 97 and the managed release-fact surface count to 8.

The bundled local Codex plugin validator retains its documented stale-schema rejection of the unchanged supported `hooks`, `brandColorDark`, and `supportURL` fields. Claude Code strict offline package validation passes. Authenticated Claude Code host and lifecycle validation was not run and remains `UNAVAILABLE / NOT-RUN` in the checked-in evidence boundary.
