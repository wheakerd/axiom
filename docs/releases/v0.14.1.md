# Axiom v0.14.1

Version `0.14.1` corrects the activation boundary for
[Delegate Simple Task](../../skills/delegate-simple-task/SKILL.md).

## Activation And Migration

The skill activates only through an enabled, active `using-axiom` gate when
current host context verifies user-selected `Ultra` reasoning and the user
has confirmed or explicitly authorized invocation. If the first two conditions
hold but consent is missing, the gate asks once and waits before loading the
skill. Direct invocation supplies consent only; it cannot bypass gate or
reasoning checks.

Automatic activation without invocation consent is removed in this version.
Full Access does not waive activation conditions. Missing, disabled, or
unverified gates and non-Ultra or unknown reasoning keep the task in the main
session. Axiom does not change host settings to satisfy these prerequisites.
Existing in-scope invocation consent is retained; new assignments recheck
current gate and effort evidence. Assignment authorization stays separate.

Users who want this workflow enable the gate, select Ultra, and confirm or
explicitly authorize invocation. Other users need no configuration change.
The skill's UI metadata disables implicit invocation and its source repeats
the activation check for direct loads.

## Validation Boundary

The [acceptance examples](../../skills/delegate-simple-task/references/delegation-contract.md#acceptance-examples)
cover invocation consent, disabled or unknown gates, non-Ultra and unknown
effort, Full Access, direct requests, and resume. They are instruction
contracts, not recorded host executions.

The original `codex-core-v4` benchmark retains its medium-effort delegation
expectation and immutable contract. It cannot establish this version's Ultra
gate behavior. The [evaluation guide](../../evals/README.md) records that
limitation; a successor host contract is required before making that claim.

The candidate remains `STATIC-ONLY`. Installation, startup delivery, native
route behavior, and publication have not been established for this candidate.
The existing marketplace selection remains unchanged.
