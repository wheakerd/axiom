# Axiom v0.21.0

Version `0.21.0` changes how `delegate-simple-task` decides whether to delegate. The host's verified top reasoning level is no longer an activation condition; the main session judges whether it can state the assignment completely and check the result. Invocation consent and assignment confirmation now share one question. The startup routing gate, the Hooks, and every other skill are unchanged.

## Why A Minor

The [release standard](../runtime-identity.md#version-increment) assigns a minor increment to a changed protocol. The activation contract of `delegate-simple-task` changes: a documented condition is removed, two confirmations become one, and on Codex an explicit invocation can now reach assessment instead of stopping at the activation check. No route is added or removed.

## Why The Condition Went

The condition used a host setting as a stand-in for a judgment the model can make itself, and the setting is often invisible to the model. The [v0.19.2 note](v0.19.2.md) recorded that Codex exposes no reasoning-level fact a session can verify, so an explicit invocation there could only end in a stated stop. A skill should give direction and leave the decision to each host's model. The guidance that replaces the condition names what the decision depends on: whether the main session can specify the work completely and verify the result.

## What Changed

- `SKILL.md`: the description states what the skill does, when to use it, and when not to, and keeps the `model`, `permission-bypass`, and `confirmation` selection anchors. The Activation section has two conditions, the active `using-axiom` gate and the user's consent, and states that the reasoning or effort level is not a condition. Eligibility gains the main session's fit judgment. The decision table and the permission-bypass paragraph take consent from an explicit invocation or a standing delegation policy.
- `references/delegation-contract.md`: consent and assignment confirmation share one question. The acceptance examples drop the reasoning-level cases and add one that proceeds when the host reports no level or the session runs below the host's top level.
- `references/host-evidence.md`: the top-reasoning-level signal is removed; unknown gate evidence still keeps the skill inactive.
- `agents/openai.yaml`: the short description and default prompt no longer ask for a verified reasoning level.
- The README skill table and the Skill Reference, Architecture, Trust Model, Examples, and Runtime Changes pages describe the same activation. The offline route case `explicit-delegation-without-host-level-fact` keeps its route and phase and no longer asks the skill to stop.
- Repository tests: the catalog handoff fixture no longer adds a second `## <version> - unreleased` heading when the checked-in Changelog already declares that version, and the pinned documentation counts, aggregate summary, and current routing-context record expectations move to this candidate.

## Unchanged Boundaries

The active gate is still required, and an inactive or unverified gate still stops the skill with the reason stated. A permission-bypass mode still cannot supply consent. The user's ordered candidate list, the exact-model brief, the ban on changing model, reasoning, permission, or subagent settings to make delegation possible, and every assignment boundary remain.
