## Local Web Research

The new [Local Web Search](../../skills/local-web-search/SKILL.md) route applies
before a local browser or client searches the web or reads research pages,
including after a cloud-to-local fallback. Confirmed cloud-hosted search stays
outside; an unknown execution location is classified from available tool
information and provisionally receives the same constraints.

The workflow avoids agent-added machine information, sends research requests
in sequence, preserves browser identity, and stops a site's automated access
at a challenge, CAPTCHA, or rate limit. User handoff preserves the current page
and waits for explicit readiness. Client switching and identity spoofing
cannot be used to bypass the stop. Cloudflare's classification is outside the
skill's control; no guarantee against bot detection is claimed.

## Document Language

New or rewritten prose in root and nested `AGENTS.md`, linked `.agents`
instructions, and explicitly scoped repo-local Skills defaults to English.
Only an explicit user request for those documents selects another language,
within the requested file or document scope. A non-English task, reply request,
explanation request, existing document, or source does not supply that choice.

The contract stays in the always-loaded parent of the selected capability,
including narrow maintenance paths that do not load the document-contract
reference. It preserves canonical identifiers, commands, paths, exact source
literals, unrelated content, and the actual active instruction chain. It is
not inserted as target-repository policy unless the user explicitly asks.

Acceptance inspects authored prose in every changed instruction file. The
semantic review cases cover default language, response-only instructions,
explicit scoped overrides, source language, narrow maintenance, compaction,
and instruction conflicts. Source review checks these decision boundaries;
structural validation does not prove model-generated output behavior.
