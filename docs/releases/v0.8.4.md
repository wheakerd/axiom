# Axiom v0.8.4

Version `0.8.4` is the sequential candidate for Issue #37.

## Host-Native Ordinary Pushes

<!-- route-boundary:traceable-git-submit-v1:start -->
Ordinary named-remote, non-force staging, commits, and pushes stay host-native when they
include neither a tag nor a traceable trigger. A combined commit, tag, and push of an
already-prepared plugin release selects `traceable-git-submit`'s hardened phase. The
traceable triggers are an explicit `$traceable-git-submit` invocation, checkpoint,
baseline, consolidation, recovery, multi-target, force, and history replacement. Merely
mentioning `submit`, `publish`, or `push` does not select the route.
<!-- route-boundary:traceable-git-submit-v1:end -->

No match is neither denial nor authorization. For a combined commit and push,
the exact expected staged payload is normal host state; it does not manufacture
a repository-state conflict. Only concrete current evidence of drift, extra or
unknown staged paths, an in-progress operation, force or target widening,
instruction conflict, or known divergence stops before commit. An unchanged
authorized envelope is not reconfirmed.

An explicit `$traceable-git-submit` simple push loads only
`references/direct-submit.md`. That phase preserves the named remote and branch,
keeps repository hooks active, pushes once, and treats normal Git output and a
normal tracking update as primary evidence. It makes no query after a conclusive
result and at most one owning-remote query after material ambiguity. It never
substitutes a raw URL, fingerprints a normal target, creates a wrapper or
generated runner, adds `--no-verify`, fetches, forces, widens, or retries.

Heavyweight raw-target, compare-and-swap, backup, checkpoint, consolidation,
recovery, history-replacing, and multi-target controls remain under their
existing phase owners. A stale tracking ref alone does not block normal Git's
safe live fast-forward negotiation.
