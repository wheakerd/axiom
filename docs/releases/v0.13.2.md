Version `0.13.2` corrects existing Git submission and recovery, rollback
preparation, and packaged-plugin readiness contracts. These are compatible
fixes to promised workflows, with no new public capability.

## Git Submission And Recovery

Prepared plugin releases have an explicit phase for authorized commit, branch,
and tag submission. Its exact branch and tag baselines, transport constraints,
and verification remain separate from existing-commit pushes and consolidation.
Multiple authorized destinations may have different ancestor baselines; each
destination retains its own proof and drift check.

Consolidation recovery validates a backup ref as a ref name and checks its
resolved commit. Cleanup persists exact deletion intent before deleting that
ref, so interrupted cleanup can reconcile an absent ref without inventing
authority or claiming who removed it. Recovery still requires current identity,
destination, containment, and authorization evidence.

## Recovery Material Preparation

Missing backups can be prepared in a bounded, authorized phase before a
restore-validated rollback point exists. Preparation must establish isolation,
its exact write set, and failure disposal. It does not change active state or
pass the full rollback gate. Candidate and active-state mutations still require
current restore validation and the complete recovery evidence set.

## Target-Owned Release Readiness

The plugin architect derives identity, versioning, distribution gates, and
report fields from the target repository's observed release contract. Local
marketplaces and non-GitHub flows do not inherit Axiom-specific infrastructure.
`notApplicable` requires direct contract evidence; missing access, tools, or
observations cannot use that label. The readiness phase remains read-only and
grants no authority for later release actions.
