# Axiom v0.8.0

Released: 2026-08-23

Version `0.8.0` implements Stage 2 of
[Issue #33](https://github.com/wheakerd/axiom/issues/33) and the accepted
[`agent-plugin-architect` route contract](../agent-plugin-architect-route-contract.md).
The new public route changes installed capability, so this candidate advances
the minor version rather than extending the v0.7 patch line.

The immutable Git tag `v0.8.0` will identify the published release. This local
candidate does not create a tag, GitHub Release, pull request, or other remote
state.

## Packaged Architecture Route

The shared package now includes `skills/agent-plugin-architect/` with the
accepted narrow English trigger contract. Its root directly exposes seven
references for:

- package inventory;
- route and trigger contracts;
- packaged Skill architecture;
- hooks and trust boundaries;
- cross-host packaging;
- evaluation and evidence; and
- validation reporting.

The Skill is packaged once under the shared `skills/` tree used by Codex and
Claude Code. There is no nested Skill, host-specific copy, scan-only jump node,
new startup hook, runtime dependency, service, background task, network check,
credential access, telemetry, or updater.

The route selects only explicit packaged Codex or Claude Code plugin
architecture involving shared Skills, routes, manifests, wrappers, hooks, or
version-bound compatibility evidence. Repo-local `AGENTS.md` and
`.agents/skills` work remains under `agents-architect`. Generic plugin code,
VS Code extensions, parser work, and ordinary README work remain no-route.
Usage optimization or retrospective review may compose only when explicitly
requested, with at most two routes. Git submission, installation, publication,
deployment, and external actions re-route by active phase and retain separate
authority.

## Shared Package And Trust Boundary

- Both manifests advance together from `0.7.12` to `0.8.0`; every other
  manifest field remains unchanged.
- Both marketplace wrappers and both hook documents remain byte-identical.
- The hooks retain only their existing foreground output and local gate read;
  `SessionStart` matchers and commands do not expand.
- README, architecture, examples, trust, compatibility, and release documents
  describe the same seven-route, eight-direct-Skill inventory.
- Static package presence, manifest parity, and offline validation do not prove
  authenticated discovery, lifecycle routing, model behavior, marketplace
  acceptance, or portal behavior.

## Evaluation And Context Evidence

The frozen v1 corpus schema, both historical response schemas, the
`codex-core-v1` benchmark, all historical routing JSONL files, all nine host
observations, and every earlier context record remain byte-identical. Additive
v2 contracts introduce the current seven-route corpus schema, the prose-free
five-field `host-response-schema-v3.json`, and the 17-case `codex-core-v2`
benchmark.

multilingual, untrusted-data, and compaction boundaries. Static validation
counts 30 memberships across the 13-case historical benchmark and the 17-case
current benchmark, while the nine historical observations remain bound only to
v1. No current host result is inferred.

The public [v0.8.0 routing-context record](../../evals/context-budget/results/v0.8.0.json)
measures the always-loaded gate at 6,150 UTF-8 bytes, 788

`9ef0c0e28bb3ad1f91d2cc2014ab18b09bffd74ad402c3190a2f4949c48ebfd1`.
The 1,538 `ceil(bytes / 4)` value is a comparison estimate, not exact host
usage. Against immutable v0.7.9, the exact delta is +251 bytes, +31 words, +4

All seven lifecycle scenarios retain one checked-in expected injection and no

## Release Validation

Candidate validation runs from frozen disposable copies outside the publishable
worktree. It covers the complete standard-library suite, distribution drift,
compatibility evidence, routing-context reproduction, aggregate publication
policy, the changed-Skill quick validator, duplicate-aware JSON and JSONL,
Markdown links and fragments, ASCII-only public definitions, instruction byte
limits, direct-reference reachability, package shape, manifest and hook parity,
exact paths and modes, historical byte preservation, diff hygiene, and brand
and documentation invariants.

All 63 standard-library tests passed. Aggregate publication validation passed
with 58 required files, 84 Markdown files, 47 offline route fixtures, 64 corpus
cases, 30 benchmark memberships, nine preserved host observations, seven
context scenarios, five source-linked route contracts, 21 manifest fixtures,
and four hook-lifecycle fixtures. Distribution drift passed with eight shared
Skills; compatibility evidence passed with two records and ten negative
fixtures; routing-context reproduction passed all seven lifecycle slots
without claiming host usage.

The duplicate-aware scan parsed 31 JSON files and 64 records across 11 JSONL
files. All 129 Markdown, JSON, YAML, and YML files passed exact ASCII decoding;
all 84 Markdown files passed local link and fragment validation. Instruction
size, direct-reference reachability, no-nested-Skill shape, manifests, hooks,
path modes, historical bytes, whitespace, and documentation and brand checks
passed.

The changed Skill passed the local Skill Creator quick validator. Claude Code
`2.1.220` strict offline package validation passed in an isolated configuration
directory; it is not authenticated host behavior. The bundled
`plugin-creator` retained exactly its known stale non-pass for `hooks`,
`interface.brandColorDark`, and `interface.supportURL`; that diagnostic was not
weakened into success.
