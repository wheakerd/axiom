# Axiom v0.3.0

Released: 2026-07-29

Version `0.3.0` added a Claude Code distribution alongside Codex while keeping
one shared source for Axiom's public workflows. The immutable Git tag `v0.3.0`
identifies commit `94f870d800288ba09f2a9874a7e31b520b965832`.

These notes describe checked-in repository state and validation recorded in
the tagged history. They do not assert that a GitHub Release page exists or
that GitHub marks this version as Latest; that remote release state was not
verified for this documentation work.

## Highlights

### Claude Code support

The release added:

- `.claude-plugin/plugin.json` for the Claude Code plugin wrapper.
- `.claude-plugin/marketplace.json` for the Claude Code marketplace entry.
- `hooks/claude-hooks.json` with `SessionStart` handling plus `PreCompact`
  handling for manual and automatic compaction.

Claude Code and Codex both load the checked-in `skills/` directory. There is no
second copy of a skill to reconcile between hosts.

### Separate platform wrappers

Host integration remains explicit and independently reviewable:

| Surface | Codex | Claude Code |
| --- | --- | --- |
| Manifest | `.codex-plugin/plugin.json` | `.claude-plugin/plugin.json` |
| Marketplace | `.agents/plugins/marketplace.json` | `.claude-plugin/marketplace.json` |
| Hooks | `hooks/codex-hooks.json` | `hooks/claude-hooks.json` |
| Skills | `./skills/` | `./skills/` |

Both hook definitions read `skills/using-axiom/SKILL.md`. Claude Code owns its
additional compaction behavior without making Codex discover the Claude Code
hook. The conventional cross-platform `hooks/hooks.json` path is absent.

### Distribution drift guard

The release added `scripts/check-distribution-drift.py` and the
`distribution-drift` GitHub Actions workflow. The standard-library script
compares direct skill entries on disk with:

- The Codex manifest and marketplace wrapper.
- The Claude Code manifest and marketplace wrapper.
- The parseable shared-skill list in `README.md`.

The workflow runs the check on pull requests, pushes, and manual dispatch with
read-only repository permissions and a bounded timeout. It is a contributor
and CI check, not an installed Axiom runtime dependency.

## Historical validation evidence

The `v0.3.0` commit history records these release-preparation results. They are
historical evidence, not a claim that the same tools were rerun while writing
this document:

- Distribution drift positive and negative cases passed.
- Claude Code `2.1.220` strict marketplace and plugin validation passed.
- JSON and YAML parsing, hook/document parity, Unix hook execution, skill-tree
  shape, English and brand scans, size checks, whitespace checks, and final
  diff checks passed across the two preparation commits as recorded there.
- Both platform manifests were synchronized at version `0.3.0` before the

## Legacy Codex validator discrepancy

The two v0.3.0 preparation commits record one compatibility discrepancy: the
legacy local Codex `plugin-creator` validator rejected the `hooks` field in
`.codex-plugin/plugin.json`, while the release work recorded that the current
official schema supported that field. The intentional declaration
`"hooks": "./hooks/codex-hooks.json"` was retained.

That historical validator result must not be reported as a pass, but it also
is not evidence that the checked-in hook declaration should be removed. When
reproducing the check, record the validator version and its exact result so a
legacy-schema conflict remains distinguishable from a current packaging
defect.

## Known limits

- Axiom provides four narrowly routed workflows; it does not route every
  coding or documentation request.
- Loading a route does not authorize a commit, push, deployment, deletion,
  promotion, credential use, or other mutation.
- Hooks are foreground local-file reads that still require host installation,
  review, trust, and session reload behavior to work as documented.
- Axiom has no background service, automatic updater, or installed runtime
  dependency. Marketplace refresh and plugin updates remain explicit host
  actions.
- The recorded validation covers the tools and versions named above. It does
  not establish compatibility with every host release, operating system, or
  shell.
- In this repository checkout, the `latest` tag points to the same commit as
  `v0.2.1`; it does not identify `v0.3.0`. Use the immutable `v0.3.0` tag for
  this release.
- GitHub Release existence and GitHub's Latest marker were not verified and are
  not claimed here.
