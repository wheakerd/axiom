# Axiom v0.23.0

Version `0.23.0` acts on the independent review of 0.22.1 and on a private audit of local sessions that found the plugin selecting routes too rarely where it should help and loading skills where it should not. Four routes narrow to the conditions where their direction helps, `delegate-simple-task` activates on an explicit request even when the startup gate was not delivered, the bundled descriptions shrink to their selection conditions, the startup gate becomes the single owner of the delegated-choice rule, `traceable-git-submit` keeps only the invariants that plain Git can express and runs repository hooks by default, and the marketplace listing describes routing rather than guardrails.

## Why A Minor

The [release standard](../runtime-identity.md#version-increment) assigns a minor increment to changed route matching with a migration note and to a changed protocol. Four documented triggers change, `delegate-simple-task` widens to an explicit invocation without the gate, and the traceable Git protocol changes its hook policy. No route is added or removed.

## What Changed

- `traceable-git-submit` (Issue #222): eight references replace twelve, 39,827 bytes instead of 76,355. Every phase keeps normal repository hooks active and adds `--no-verify` only when the user explicitly authorized bypassing this repository's pre-push hook for the exact push; the three push commands that added the flag by default are gone, along with the `-c push.*` overrides. The heavy phases keep their named invariants, compare-and-swap `update-ref --no-deref` for every branch install or restore, a create-only backup ref before any history replacement, no `reset --hard`, `stash`, or `clean`, an exact frozen NUL-safe path set, one push per frozen target with `ls-remote` read-back, and no automatic retry after an uncertain result, and drop the byte-level commit parsing, Unicode category checks, no-follow file semantics, sibling locks, and endpoint fingerprints. Git-metadata state keeps its `rev-parse --git-path` locations under a documented single-writer assumption. The route-boundary catalog, the offline route model, the Git contract fixtures, and the trust model follow the new reference set.
- `local-web-search` (Issue #223): the gate selects it only for research that will run through the user's own browser, CLI, script, or HTTP client, or that the user says runs on their machine, including a fallback from cloud search to such a client; a host's built-in web tool stays host-native, and the "uncertain execution location" branch is gone from the gate, the description, and the skill.
- `verify-completion` (Issue #223): the description and Apply When drop the "resumes after compaction with unfinished mutations" trigger. The gate alone owns the compaction moment and says that routine continuation after compaction selects no route; the skill fires on an explicit verification request or a completion claim, including one carried by a compaction summary.
- `task-planning` (Issue #223): fires on a revision of an existing plan (remove, replace, merge, reorder, narrow) or an explicit invocation; a fresh plan request stays host-native.
- `delegate-simple-task` (Issue #223): an explicit invocation or a clear delegation request activates the skill. Gate delivery is advisory context: when the gate was delivered it already resolved ambiguity, and when it was not, for example in Codex before the Hook is trusted, the skill says so and assesses ambiguity in the main session. Candidate models are named the way the host names them; `references/host-evidence.md` describes the signals.
- Descriptions (Issue #224): all fourteen descriptions carry only their selection conditions and nearest exclusions, none above 450 characters; the set measures 5,071 bytes against the 7,250-byte 0.22.1 baseline in the [routing-context record](../../evals/context-budget/results/v0.23.0.json). The delegated-choice rule has one owner, the startup gate; `clarify-intent`, `task-planning`, `agent-plugin-architect` and its route-and-trigger contract, `traceable-git-submit`, and `reversible-system-change` point at it with one sentence, and the validator pins the gate copy only (seven source-linked contracts instead of thirteen).
- Packaging (Issue #225): the Codex manifest's short description reads "Route before the agent acts", the keywords drop `agent-safety` and `workflow-guardrails` for `workflow-routing`, and the long description states that Axiom adds instructions, not enforcement. `continuous-progress` states its scheduler requirement in its description and Codex default prompt: the supervisor needs a Desktop or cloud scheduled task or GitHub Actions, and a CLI session alone cannot wake it; the README row inherits it.

## Routing Contract v7

Changed expectations need a new contract version, so [schema v7](../../evals/schema-v7.json) and [routing-v7](../../evals/routing-v7/current.jsonl) replace v6 for new observations. Two v6 cases retire because their expectation changed, five cases with new IDs encode the narrowed triggers, and the `codex-core-v7` and `claude-code-core-v7` profiles select 40 cases: the v6 order without the retired case, the plan-revision case as the route's canonical trigger, and four new cases. Schema v7 records bind response schema V8 only; v6 records stay verifiable against their own contract. The Codex profile runs `gpt-6-astra` at maximum reasoning effort with a 300-second case timeout, because Codex CLI 0.166.0 refuses the earlier `gpt-5.4` profile on a ChatGPT account; the Claude Code profile keeps `claude-opus-5-5` at maximum effort. The offline route model regression-tests the five new expectations.

## Unchanged Boundaries

Routing still selects instructions only. `delegate-simple-task` consent, the external-action authorization gate, the rollback evidence gate and its informed waiver, untrusted-input handling, and every other stop condition stay hard. A delegated choice still settles only under the gate's rule: every alternative reversible and already authorized, the pick and why stated before acting, and no persistent system change, external or remote-state change, deletion, credential use, or material cost authorized by an offered option.
