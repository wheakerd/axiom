# Axiom v0.6.1

Released: 2026-08-18

Version `0.6.1` is a compatibility and trust-boundary hardening release. It
keeps the same six public Skills while fixing Codex starter-prompt truncation,
making every canonical AGENTS update mode visible at the selection surfaces,
repairing a broken validation reference, and aligning update documentation
with host-controlled auto-update behavior.

The immutable Git tag `v0.6.1` identifies this release. Consumers that need a
stable source identity should use that tag rather than a moving alias or
floating branch.

## Highlights

### Codex starter prompts fit the host contract

The Codex manifest now declares three starter prompts, matching the host's
display limit. Entries that were already ignored after the third position are
removed, and the AGENTS starter now asks for an audit and report only instead
of ambiguously combining audit and refactoring.

Publication validation now rejects more than three prompts, empty entries, and
entries beyond the host's character limit. It also requires strict SemVer and
the expected Axiom identity, display name, category, and marketplace policy.

### Public routing surfaces match the canonical modes

`agents-architect` and the `using-axiom` front door now expose all six
canonical effective-instruction modes:

- `effective-instructions`
- `effective-instructions:preview`
- `effective-instructions:refactor`
- `effective-instructions:force <instruction>`
- `effective-instructions:reconcile`
- `effective-instructions:reconcile-preview`

The offline routing guard checks both the front-door entry and packaged Skill
description instead of comparing only two hard-coded models in the same
script. It exercises all six modes and still keeps ordinary no-match,
authorization, Git, review, optimization, ambiguity, and persistent-change
controls.

The agents-architect validation route now links to its actual sibling
`instruction-document-contracts.md` owner. Repository-relative link validation
will reject the former broken `../` path if it returns.

### Update and removal boundaries reflect host behavior

Axiom still contains no updater, service, watcher, or background task. The
host owns marketplace refresh and plugin installation. Claude Code may update
marketplaces and installed plugins on disk after startup when auto-update is
enabled; third-party and local development marketplaces keep that setting off
by default, but a user or administrator can enable it.

The README now distinguishes manual refresh from configured auto-update,
requires renewed hook review after a snapshot changes, and documents exact
host-managed commands for removing Axiom from Codex or disabling and
uninstalling it from Claude Code. Manual cache deletion and installed-package
editing remain outside the supported lifecycle.

## Compatibility and package shape

- Both plugin manifests declare version `0.6.1` and point to `./skills/`.
- The direct public Skills remain `using-axiom`, `agents-architect`,
  `optimize-codex-usage`, `review-axiom-task`, `traceable-git-submit`, and
  `reversible-system-change`.
- Hook commands, marketplace source paths, route identifiers, and installed
  runtime dependencies are unchanged.
- The release adds no edit, commit, push, deployment, credential, telemetry,
  update, disable, uninstall, or background-work authorization.
- Existing `0.6.0` installations remain compatible; the host controls when a
  newer installed snapshot becomes active in a session.

## Release validation

The release candidate was checked from the repository and, for validators that
could write, from a disposable copy outside the publishable tree. The recorded
workflow verified:

- distribution and publication agreement for 20 required files, 6 JSON files,
  47 Markdown files, 21 routing scenarios, 10 rollback scenarios, both
  marketplace wrappers, release documentation, and version `0.6.1`;
- both manifests and marketplace descriptors, both declared hook files, exact
  documented hook commands, public links, frontmatter, reference discovery,
  packaged Skill layout, identity fields, lifecycle commands, and synchronized
  version metadata;
- all six packaged Skills with the local Skill Creator quick validator;
- Claude Code `2.1.220` strict plugin and marketplace validation, English-only
  public definitions, instruction-size limits, whitespace, and absence of
  private or generated artifacts; and
- negative checks that rejected a fourth Codex starter prompt, a missing
  canonical route token, the former broken relative link, and non-strict
  SemVer.

The bundled local `plugin-creator` validator rejects the Codex manifest's
intentional `hooks` field. This remains a validator discrepancy, not a pass.
Codex CLI `0.147.0` exposes no native plugin validation command.

The static scenarios validate checked-in contracts. A fresh Codex or Claude
Code session-level semantic-routing check and real install, disable, or removal
operations were not run and are not implied by the repository checks.

## Known limits

- Static source and scenario checks cannot prove model route selection in a
  fresh host session.
- Claude Code background updates change the snapshot on disk; the running
  session keeps the version loaded at launch until plugins are reloaded or a
  new session starts.
- Third-party and local marketplace auto-update defaults can be changed by a
  user or administrator, so the absence of a manual refresh does not prove the
  installed files are unchanged.
- A previously trusted hook must be reviewed again after the installed
  snapshot changes.
- The immutable `v0.6.1` tag, not a moving alias, is the stable release
  identity.
