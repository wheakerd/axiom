# Axiom v0.8.5

Version `0.8.5` is the contiguous candidate for
[Issue #56](https://github.com/wheakerd/axiom/issues/56). It is a compatible,
repository-only CI security hardening release. Installed Skills, hooks, route
selection, action authority, manifests other than their synchronized version,
and runtime dependencies are unchanged.

## Complete Pull-Request Validation

The new `Unit and integration tests` workflow runs for pull requests targeting
`main` and pushes to `main`. Its single stable check is
`unit-and-integration-tests`. It uses the fixed `ubuntu-24.04` runner label,
Python `3.14.7`, Node.js `24.19.0`, and the complete command:

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

The workflow prints `/etc/os-release` plus the Python, Node.js, and Git versions
before testing. It pins checkout, setup-python, and setup-node to full commits,
disables setup-node package-manager caching, grants only `contents: read`, and
sets `persist-credentials: false`. It contains no secret or token expression,
matrix, compatibility job, write permission, or `pull_request_target` path.

`repository-guards` remains the separate package and publication-policy check.
`Release signature guard` remains the separate post-protected-history release
provenance check. Both existing workflow files are unchanged.

## Fail-Closed Static Contract

The standard-library action-graph policy now validates the exact new workflow
name, triggers, permission, stable check name, runner, timeout, Action pins,
toolchain versions, cache opt-out, environment report, and unittest command.
Focused mutations cover write permission, `pull_request_target`, a moving
Python version, and a secret expression. Existing pull-request event fixtures
require both read-only checks for same-repository and fork proposals while
continuing to keep release provenance outside pull-request execution.

This static contract detects checked-in drift. It does not prove that GitHub
scheduled a run, withheld fork secrets, or enforced a required check.

## Governance Boundary

On 2026-08-26 UTC, the repository owner updated and then directly re-read the
active `require-signed-commits-on-main` ruleset. It now requires both
`repository-guards` and `unit-and-integration-tests` from GitHub Actions with
strict branch synchronization. The updated dated observation is recorded in
`docs/repository-governance.md`; a checkout cannot reproduce that external
configuration by itself.

Signed commits, squash-only pull requests, non-fast-forward protection, and the
release-tag signature, required-check, deletion, and non-fast-forward rules are
not changed by this repository patch. A passing local test or static workflow
contract is not reported as server-side enforcement.

## Routing And Evidence Boundary

The always-loaded `using-axiom` gate is unchanged at 7,739 UTF-8 bytes, 1,001
whitespace-delimited words, 135 logical lines, one direct reference, and SHA-256
`7da583bb99880157a7fbca539ebb0426f49cd79d2748be51e5ef5fe85eaa3996`.
The fixed routing workload remains 67 cases with all 30 frozen benchmark
memberships unchanged. No route, corpus, benchmark, model, reasoning, hook,
telemetry, or installed behavior changed for this CI-only release.

The checked-in release status remains `STATIC-ONLY`. The main-ruleset
configuration has separate direct external evidence; final candidate GitHub
Actions runs, merge-block scenarios, a real fork run, and current Codex host
and lifecycle evidence remain `NOT-RUN`. Authenticated Claude Code host and
lifecycle evidence is `UNAVAILABLE / NOT-RUN`. v0.8.4 and all earlier
observations remain separate historical evidence and are not promoted to this
candidate.
