# Axiom v0.13.4

Version `0.13.4` shortens the always-loaded startup routing document while
retaining its routes, selection conditions, authority boundaries, and safety
rules. No rule moves to an optional reference, and no model or reasoning
setting changes.

## Startup Headroom

The routing gate must use at most 6,963 UTF-8 bytes to leave at least 15% of
the 8,192-byte instruction boundary available. The publication aggregate now
checks the actual gate bytes against that limit. Boundary regression coverage
accepts 6,963 bytes and rejects 6,964 bytes, even when the recorded metrics
claim a smaller size.

The [routing-context record](../../evals/context-budget/results/v0.13.4.json)
binds the shortened document to its immediate v0.13.3 predecessor. The
immutable v0.7.9 measurement remains the separate cumulative growth baseline.
Earlier measurement records and version notes retain their original bytes.

## Preserved Contracts

The edit retains the same eleven task routes, two direct references,
frontmatter, and route order. Clause review covers:

- explicit invocation or a clear description match, minimal installed-skill
  loading, and normal no-match continuation;
- local-research reassessment before access, including a cloud-to-local
  fallback;
- clarification before mutually exclusive action choices and before
  delegation, with Full Access separate from intent and authority;
- independent external-action and persistent-change authorization, and the
  existing credential-lifecycle ownership split;
- direct-evidence reconstruction before resume or compaction can mutate;
- foreground, read-only startup without network, telemetry, or automatic
  update activity; and
- existing authorization, no-policy status for prior assistant prose, and
  explicit-only update requests.

Paired static acceptance uses the same fixed 95-case corpus, including 26
no-route controls, with source-contract and safety fixtures against both
documents. The current 27-case corpus and benchmark are checked separately.
These checks and clause review assess declared contracts; they do not execute
every natural-language request or establish installed-host behavior.

## Identity And Evidence

Startup Markdown is a classified runtime input, so its changed bytes receive
patch candidate `0.13.4` and a new runtime digest despite unchanged intended
behavior. Policy revision 47 binds the new candidate and headroom check;
revision 46 and the preceding documentation changes remain preserved.
The runtime history adds the verified immutable v0.13.3 subject without
creating an immutable entry for the new candidate.

The candidate remains `STATIC-ONLY` with a `pending-immutable-tag` binding.
Installed-host and lifecycle observation remain `NOT-RUN`. Preparation does
not create a tag, Release, publication result, or installed-session result.
