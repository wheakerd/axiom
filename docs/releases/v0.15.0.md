# Axiom v0.15.0

Version `0.15.0` restores Claude Code as a supported installation and runtime
host and delivers the Git submission hardening first tagged as `v0.14.6`. It is
a new-capability installed-runtime change; the
[runtime identity](../runtime-identity.md) owns its digest and policy revision.

## Claude Code Support

The [Claude Code manifest](../../.claude-plugin/plugin.json) packages the same
`skills/` source as the Codex plugin. Its
[startup hook](../../hooks/claude-hooks.json) runs at `startup`, `resume`,
`clear`, and `compact`, prints a short Claude Code preamble, and reads the
unchanged `using-axiom` routing gate. The [hook reference](../reference/hooks.md)
owns the exact command. The hook writes nothing, uses no network, and starts no
background process.

Shared routes load natively in Claude Code. `delegate-simple-task` requires a
verified Codex `Ultra` selection, `optimize-codex-usage` reduces Codex credits,
and `continuous-progress` supervises work through verified Codex native
scheduling. In Claude Code those three routes report that they are not
available instead of simulating Codex behavior. The startup preamble and the
[installation guide](../guides/managing-installation.md) state this boundary;
no shared Skill text changed, so Codex sees the same installed routes as in
`v0.14.6`.

Claude Code installs Axiom from the `axiom` marketplace in this repository.
Like the Codex catalog, that marketplace selects an immutable release tag and
advances only after the selected GitHub Release is verified as Latest.

## Runtime Contract Schema v3

The [schema v3 input policy](../../axiom_validation/runtime-contract-inputs-v3.json)
adds the Claude Code manifest's `name`, `skills`, and `hooks` fields to the
installed contract; the Claude hook file is already covered by the `hooks/`
tree. The [schema v2 policy](../../axiom_validation/runtime-contract-inputs-v2.json)
and its [history](../../evidence/runtime-contract-history-v2.json) remain
unchanged, so every earlier digest keeps its original derivation. The
[v3 history](../../evidence/runtime-contract-history-v3.json) begins with the
immutable `v0.14.6` tag derived under schema v3. A historical derivation skips
an input that did not exist at the old tag rather than reinterpreting it.

## Git Submission Hardening

The explicitly selected simple Git submission phase checks effective
configuration immediately before every direct push and before a combined
request's commit, and stops on automatic tag following, push options,
submodule-pushing recursion, mirroring, mapped force or divergent destinations,
remote groups, and an inherited `GIT_NAMESPACE`. The
[v0.14.6 notes](v0.14.6.md) remain the detailed record of this change.

## The v0.14.6 Tag

The immutable `v0.14.6` tag targets
`690e3f3ffd2c935863a2b32ac127d4068572b93d`. Its Changelog entry used
column-width line breaks, and the publisher must reproduce that entry
byte-for-byte as the Release body, which GitHub renders with broken lines. Under
the [fix-forward boundary](../maintainers/release-documentation.md#fix-forward-boundary)
that tag was preserved unchanged and not published as a GitHub Release; this
version carries its changes. From `0.15.0`, the release-body renderer rejects a
Changelog entry whose paragraph or list item spans more than one source line.
