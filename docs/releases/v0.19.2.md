# Axiom v0.19.2

Version `0.19.2` makes an explicit `delegate-simple-task` invocation route
deterministically on both hosts. The startup routing gate
`plugin/skills/using-axiom/SKILL.md`, the skill description and activation
section in `plugin/skills/delegate-simple-task/SKILL.md`, and its
`host-evidence.md` and `delegation-contract.md` references now state that
route selection comes first and that the skill's own activation check decides
what happens next. Hooks and every manifest field other than the version are
unchanged. The [runtime identity](../runtime-identity.md) owns the digest and
policy revision.

## Why A Patch

Issue #186 observed that fresh Codex sessions routed the canonical explicit
request only about half of the time, each miss being a silent no-route answer
with no clarification. The gate entry and the description made the host's
verified top reasoning level a precondition of invoking the skill at all, and
Codex exposes no reasoning-level fact the model can verify inside the session,
so the model sometimes treated the condition as unmet and declined without
saying so. The [release standard](../runtime-identity.md#version-increment)
classifies an evaluation-driven false-negative fix without new capability as
a patch.

## What Changed

- The gate entry begins with "an explicit invocation selects this route" and
  states that unknown gate or level evidence stops inside the skill with the
  unmet condition stated, never a silent no-route. The three activation
  conditions (active gate, verified top reasoning level, prior consent), the
  consent question, and the permission-bypass boundary are unchanged. The
  selection anchors `model`, `permission-bypass`, and `confirmation` remain in
  the entry and the description.
- The skill description and its Activation section separate selection from
  activation: selection loads only the skill file; assessment, assignment, and
  the delegation contract still require all three conditions. When the gate is
  disabled, absent, or unverified, or the reasoning level is below the top or
  unknown, the skill stops, names the unmet condition and the missing host
  evidence, and continues the task in the main session.
- `host-evidence.md` states that a host whose session context reports no
  reasoning-level setting leaves the level unknown. `delegation-contract.md`
  moves invocation confirmation to the activation check and adds the stated
  stop to its acceptance examples.
- The offline route contract gains the
  `explicit-delegation-without-host-level-fact` scenario: an explicit
  invocation that mentions the missing host fact still resolves to
  `delegate-simple-task`.
- The Skill Reference, Architecture, Trust Model, and Examples pages describe
  the same selection-then-activation order.

No activation condition is widened. A host that cannot verify the top
reasoning level still never assesses candidates or spawns a subagent through
this skill; the change replaces an unexplained no-route answer with a stated
stop.
