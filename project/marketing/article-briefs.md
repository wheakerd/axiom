# Future Article Briefs

## How To Audit An `AGENTS.md` Instruction Architecture

Opening failure: two nested instruction files both appear authoritative, while a
copied historical file silently contradicts the active chain.

Cover instruction discovery, directory scope, host precedence, canonical
ownership, duplicated policy, size and routing pressure, current implementation
evidence, preview versus apply, and validation of a changed chain. Include a
read-only inventory worksheet and a no-change control. Emphasize that reading
all visible files does not make them active and that an audit does not authorize
refactoring. Disclose the author's Axiom relationship and compare repo-native
indexes, host rules, and other possible designs.

## Designing Reversible Git Publication For Coding Agents

Opening failure: a branch push succeeds, a tag points to a different object, and
cleanup removes the only local recovery reference.

Cover repository-root ownership, immutable object IDs, remote and push-URL
resolution, fetch as a distinct mutation, exact refspecs, compare-and-set
installation, hook and configuration execution surfaces, signed tags, PR and
Release separation, idempotent retries, backup refs, cleanup authority, and
system-of-record verification. Include a disposable local-remote exercise that
never contacts a public host.

## Preventing Safety Workflows From Hijacking Ordinary Coding Requests

Opening failure: a broad safety trigger turns a README summary into a lengthy
approval ceremony, teaching users to bypass the guardrail.

Cover narrow route descriptions, positive and negative fixtures, explicit
invocation, normal-continuation controls, cross-route collisions, non-English
normalization, compaction and resume behavior, friction budgets, and false-
positive reporting. Treat precision and recall as operational tradeoffs rather
than unsupported metrics. Include one routed prompt, one ambiguous prompt, and
one no-route control.
