# The Brief And The Report

Choose a form that fits the host. The brief gives a collaborator enough context to do its part, and the report gives the lead enough evidence to check it.

## Brief

- Give today's absolute date so the collaborator can interpret time-sensitive premises and distinguish a current decision from an older one.
- Name the part, its intended result, and what the lead can inspect to accept it. Include the repository, revision, or other target when it determines which result counts.
- Identify the write surface and the allowed effects, including a read-only assignment where appropriate. Call out host defaults that would add work or disclosure outside the part, such as carrying over unrelated conversation history or starting another agent. A prompt cannot narrow a host permission that is already too broad for launch.
- Give the lead's actual return address as the host exposes it, so a report or permission question reaches the session responsible for the run. A role name alone may identify several sessions.
- Identify premises that affect the work and where the collaborator can check them independently. Ask it to surface a contradiction before relying on the disputed premise.
- Explain how to return a permission question. Include the reason, exact command, and target, and wait for the user's decision through the host's channel. Distinguish a needed grant from an action already denied, since a denial stops that effect across sessions.

## Report

- Identify what changed and where the lead can observe it. For read-only work, point to the evidence for the finding.
- Give the checks actually run, what each checked, and its observed result. Separate a failed check from one that did not run so the lead knows what still needs verification.
- Name unfinished work, uncertain effects, and any action still in flight. The lead needs that state before taking ownership or assigning more work.
- Summarize any direction the user gave directly in the collaborator and what it changed for the assignment. Keep secrets out of the account. The lead needs to re-observe the result, and a report of the user's words carries no grant.
- Return open questions with the decision each needs and the reason. For a permission question, include the exact command and target so the user can decide on that action.
