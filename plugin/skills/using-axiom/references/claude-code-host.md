# Claude Code Host Facts

Verified on 2026-11-20 against the installed Claude Code 2.1.311 help output (`claude --help`, `claude agents --help`) and the Claude Code documentation as read that day; maintainer observations date to 2.1.308 on 2026-10-30 and, where noted, 2.1.309 on 2026-11-02. Items marked (docs) restate the host documentation and need a recheck on a newer version. Run `claude --help` for the current commands and flags; this file never replaces it.

## Instructions And Skills

- At session start Claude Code loads a managed policy file, `~/.claude/CLAUDE.md`, and every `CLAUDE.md` and `CLAUDE.local.md` from the working directory upward; a project may keep its file at `.claude/CLAUDE.md`. Files concatenate root-down, so closer guidance loads later (docs).
- Subdirectory instruction files load on demand when Claude works with a file there; their presence does not prove loading. After compaction it rereads the project-root file, and nested files and path-scoped rules load again on demand (docs).
- From 2.1.277, direct discovery defaults to `AGENTS.md` and `.claude/AGENTS.md` only when the working directory and its ancestors have no project `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md`. It skips `AGENTS.override.md`, `AGENTS.local.md`, and `.agents/` (docs).
- In `/config`, set Project instructions to `claude-md-and-agents-md` to load both, with each directory's `CLAUDE.md` files first. The settings key is `pluginConfigs.cc-plugin-agents-md@builtin.options.instructionFiles` in user settings, managed settings, or a `--settings` file. Project and local settings cannot set it (docs).
- `@path` imports expand up to four hops from the importing file; `.claude/rules/` files without `paths` frontmatter load at session start; `claudeMdExcludes` skips files; `--add-dir` directories contribute instruction files only when configured (docs).
- `/context all` shows loaded instruction files under Memory files even in fullscreen mode. `/memory` also lists user and project file locations that do not exist yet (docs).
- Plugin skills appear in the skill list as `axiom:<skill-name>`, and `/axiom:skill-name` invokes one. The plugin's `SessionStart` Hook delivers the gate at session start and again after compaction with `source` set to `compact`; `/reload-plugins` applies plugin changes without rerunning it.
- The hooks documentation (`https://code.claude.com/docs/en/hooks`, read 2026-11-20) lists `UserPromptSubmit` as a current event a plugin `hooks/hooks.json` may declare. It receives `prompt`, also fires for scheduled-task firings, background subagent reports, and cross-session messages, and adds plain stdout to context; a command hook on it times out after 30 seconds by default. `PostCompact` receives the summary text; Axiom declares no compaction Hook.

## Permission Modes

- `default` (Manual) prompts natively before a tool call that needs approval; the answer is the grant.
- `auto` runs without routine prompts. Permission rules can decide a call before classifier review (docs). Present the exact command and target first in a text block. Observed 2026-11-02: text written inside a thinking block reached no notice the user could rely on, and a denial of one Bash call that mixed a read-only query with the mutation covered both. A classifier denial is a stop; the user may run the command natively or grant it again.
- The classifier reads `autoMode` from user settings, managed settings, or invocation settings supplied through `--settings` or the Agent SDK. It ignores `.claude/settings.json` and `.claude/settings.local.json` for this key (docs).
- `bypassPermissions` is the permission-bypass mode and waives no Axiom boundary. `dontAsk` denies every call that would prompt, though a mod the user installed can still approve some of those calls (docs); the mode is not a grant. `--allowedTools` and `--disallowedTools` bound a run within the user's authority; never widen them to finish.
- A subagent runs in the parent's process with the same sandbox configuration and inherits its permission mode unless a custom agent sets `permissionMode`, which Claude Code ignores for a plugin's agents. Under a parent in `acceptEdits`, `auto`, or `bypassPermissions` the subagent runs in that mode and its own setting is ignored; under a parent in `plan` an ordinary subagent stays in `plan`; under `default` or `dontAsk` its own setting applies, except that `bypassPermissions`, or `auto` where auto mode is unavailable to it, keeps the parent's mode (docs).
- A foreground subagent's permission prompts pass through to the user. A background subagent's prompt surfaces in the main session and names the subagent; approving lets it continue, and Esc denies that one call without stopping it. In `/tasks`, `Enter` opens a subagent's transcript and `x` stops it (docs).
- Agent teams are experimental and disabled by default. A teammate starts in the lead's mode, including `bypassPermissions`, except that under a lead in `dontAsk` it starts in Manual; for a split-pane teammate of a lead in Manual or `dontAsk`, the documentation gives 2.1.317 as the first version that does so. An in-process teammate runs under the lead's live allow and deny rules; a split-pane teammate starts with the lead's `--tools` and `--disallowedTools` from 2.1.309 and does not receive `--allowedTools`. The documentation read does not say whether a split-pane teammate shares the lead's sandbox configuration. Teammate permission prompts appear in the lead session (docs).
- In the agent panel, `Enter` on an in-process teammate opens its session and `x` stops it. A shutdown the lead sends is a request the teammate can approve or reject (docs).

## Running Claude Code From A Session

- `claude -p` runs one prompt from arguments, a file, or stdin; `--output-format json` or `stream-json` returns the result with its `session_id`, and `--input-format stream-json` continues the same thread.
- `--model` and `--effort` pass the observed settings to a child; `--max-turns` and `--max-budget-usd` bound it, and a cap that stops the run also stops its background subagents.
- `--resume <id>` continues a saved session and `--fork-session` gives the successor a new identity; `--no-session-persistence` saves nothing; `--bare` skips hooks, plugins, and project instructions and binds no inbox. `--plugin-dir` loads a plugin for one invocation, and `--settings` can disable an installed one.
- `claude --bg` starts a background session, which `claude agents`, `attach`, `logs`, `respawn`, and `stop` manage. A `done` state means the last turn ended, not that the assignment succeeded. Exit code 143 after SIGTERM is an unfinished turn; send SIGINT first.
- Agent view is a research preview. A session backgrounded with `/bg` keeps its permission mode. `/fork` copies the conversation into a new background session and carries over the model, permission mode, effort, added directories, and "don't ask again" grants. A background session reads its settings from the directory it runs in, as a new `claude` session there would with the flags it carried. A session dispatched from an agent view opened with the left arrow takes the target directory's `permissions.defaultMode`, then the mode of the session it came from; a project or local `defaultMode` more permissive than that session's mode is refused (docs).
- Agent view lists a session waiting on a permission decision under Needs input. Replying from the peek panel does not answer the dialog; the user attaches to answer it. A background session's Bash commands are sandboxed when its own settings enable sandboxing. In print mode, `--permission-prompts host`, the default, sends prompts to the Agent SDK host or the `--permission-prompt-tool` tool, and `none` denies them (docs).
- `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` turns off auto memory for a run that must leave no trace.

## Scheduling, Messaging, Compaction, And Cancellation

- Session-scoped `CronCreate` tasks and `/loop` fire only while their session runs and is idle, and recurring ones expire after seven days. A time that passes during a busy turn fires once when the session is idle, not once per missed interval, and runs missed while the session was not running are not caught up; `/goal` keeps one session working and is not a supervisor (docs).
- An independent wake comes only from a Desktop scheduled task (this machine, app open), a cloud scheduled task in research preview (fresh clone, one-hour minimum, no local files), or a GitHub Actions schedule (docs). Without one, no independent wake mechanism exists; never substitute a cron job, service, daemon, or startup hook.
- `ListAgents` discovers reachable sessions and `SendMessage` delivers plain text; `notify_when_idle` requests one notice when a session on this machine next goes idle or exits. A receiver's `crossSessionInbound` setting may hold or refuse a message, and a held message is not a delivered handoff (docs).
- A message from another session never counts as the user's consent and cannot answer a pending permission prompt. Claude Code instructs a session not to ask another session for an action that was denied or blocked in its own, and the receiving session's own prompts and rules still apply to what a message asks for (docs).
- `PreCompact` and `PostCompact` hooks bracket compaction. Manual `/compact` proves that path only; automatic compaction needs its own observation.
- To cancel, persist control first, stop new dispatch, disable the exact wake mechanism, then stop the active work: `claude stop <id>` for a background session, SIGINT for a foreground run, and the owning tool's cancel for subagents.
